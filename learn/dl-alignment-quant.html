⚖️ Post-training: RLHF, DPO, quantisation and reasoning models

EnglishHinglish

🏠 Real-life example

A medical graduate who has read every textbook knows millions of facts, but still needs hospital residency to learn bedside manner: how to answer patients clearly, refuse unsafe requests, and think step by step on hard diagnoses. Pre-training is reading the textbooks; post-training (SFT, RLHF/DPO, and reasoning RL) is the residency. And quantisation is printing a pocket handbook in 4-bit shorthand so it fits in your coat pocket.

💡 In simple words

A pre-trained LLM only predicts the next word. Post-training turns it into a helpful assistant in stages: Supervised Fine-Tuning (SFT) on instruction examples, then preference alignment so it prefers helpful, safe answers over bad ones. RLHF (with PPO) trains a separate reward model and runs reinforcement learning, holding four models in GPU memory. DPO (Direct Preference Optimization) simplifies this by training directly on (chosen, rejected) answer pairs with just the policy and a frozen reference model. For maths and coding, reasoning models train with reinforcement learning on verifiable answers so the model spends extra 'test-time compute' checking its own steps. Finally, quantisation (FP16 → INT8 or INT4 with AWQ/GPTQ) shrinks model weights and KV cache by 2–4× so large models run cheaply on fewer GPUs.

🪜 Step by step

  1. Start with Supervised Fine-Tuning (SFT) on clean (prompt, ideal response) examples so the model learns the target format and tone.
  2. Collect preference pairs: for the same prompt, one response is better ('chosen') and one is worse ('rejected'), graded by humans or a strong judge.
  3. Run DPO (or RLHF/GRPO for verifiable reasoning tasks) with a small learning rate and a KL penalty (beta) so the model doesn't drift too far from the base model.
  4. Mix 10–20% general instruction data into domain fine-tuning so the model doesn't suffer catastrophic forgetting of general reasoning.
  5. For deployment, quantise weights to INT8 or 4-bit AWQ/GPTQ and benchmark both accuracy on your eval set and latency/throughput before shipping.

🔑 Key terms

DPO vs RLHF (PPO)
Both align models to human preferences; DPO trains directly on preferred vs rejected pairs without a separate reward model.
Post-Training Quantisation (PTQ)
Compressing model weights from 16-bit floats to 8-bit or 4-bit integers (e.g. AWQ, GPTQ) after training to cut GPU memory.
Test-time compute (reasoning)
Letting a model generate and verify a longer chain of thought before answering hard maths, logic or code questions.

⚠️ Common mistakes to avoid

  • Quantising a model to 4-bit and deploying without running your domain eval suite: math, code and exact entity extraction can degrade first.
  • Training DPO for too many epochs or with too low a beta, causing the model to output repetitive, unnatural or sycophantic text (reward hacking).

✅ Quick check

Why is DPO (Direct Preference Optimization) often easier to run than classic RLHF with PPO?

  1. DPO optimises preference pairs directly with a cross-entropy-style loss, without training a separate reward model or running unstable PPO
  2. DPO does not need any training data
  3. DPO only works on CPU
Show answer

A. DPO optimises preference pairs directly with a cross-entropy-style loss, without training a separate reward model or running unstable PPO: PPO requires coordinating four models in memory (actor, critic, reward, reference); DPO needs only the policy and a frozen reference model.

🙋 Questions learners ask

Why do activation outliers make LLM quantisation hard, and how does AWQ fix it?

A tiny fraction (~0.1%) of weight channels carry huge activation values. Crushing those channels to 4 bits ruins accuracy. AWQ identifies those salient channels using a small calibration set and scales them to protect their precision.

When should I use a reasoning model vs a standard fast LLM?

Use a reasoning model for multi-step math, complex code generation, planning or root-cause analysis where accuracy beats latency. Use a standard fast model for chat, summarisation, extraction and routing where sub-second response time matters.

🎯 Asked in interviews on this topic

Try answering out loud first, then open the model answer.

Compare SFT, RLHF (PPO) and DPO for post-training an LLM. Why is the KL penalty needed?

💬

Supervised Fine-Tuning (SFT) teaches the base model to follow instructions by imitating curated (prompt, response) demos. RLHF goes further using human preference pairs (chosen vs rejected): it trains a separate reward model and uses PPO reinforcement learning to maximise reward while keeping a KL-divergence penalty so the policy doesn't drift too far from the SFT reference and 'reward-hack' with gibberish or sycophancy. Direct Preference Optimization (DPO) mathematically rewrites that reward + KL objective into a simple binary cross-entropy loss directly on the preference pairs, eliminating the separate reward model and unstable PPO loop. For verifiable tasks like math or code, GRPO/RLVR trains reasoning chains against unit-test rewards.

✅

  • SFT imitates demos; RLHF/DPO align using (prompt, chosen, rejected) preference pairs
  • KL-divergence penalty stops the model from drifting and reward-hacking
  • DPO optimises preferences directly with cross-entropy without a separate reward model
  • RLVR / GRPO uses verifiable code or math rewards for reasoning models

: Core 2026 post-training and alignment question for Research, ML and Agent engineers.

How does post-training quantisation (INT8/INT4, AWQ, GPTQ) work, and why do activation outliers break naive INT4?

💬

Quantisation maps 16-bit floating-point weights (FP16/BF16) onto a narrow grid of 8-bit or 4-bit integers using a scale factor, cutting GPU memory by 2× to 4× and speeding up memory-bandwidth-bound token generation. Naive round-to-nearest INT4 degrades accuracy because transformer activations above ~6B parameters develop huge outlier channels (100× larger than normal); stretching 16 integer buckets across that range squashes all normal weights to zero. AWQ and GPTQ fix this using a small calibration set: AWQ scales up the 1% of weight channels that multiply large activation outliers before quantising, preserving accuracy.

✅

  • Maps FP16/BF16 weights to INT8/INT4 grids; cuts VRAM 2–4× and speeds up token decoding
  • Transformer activation outliers stretch the quantisation grid and crush normal values
  • AWQ / GPTQ use calibration data to protect salient weight channels
  • Also quantise the KV cache (FP8/INT8) for long contexts and big batch sizes

📌 Remember

SFT teaches format, DPO/RLHF aligns preferences, reasoning RL boosts hard problem-solving, and INT4/INT8 quantisation makes serving affordable.
