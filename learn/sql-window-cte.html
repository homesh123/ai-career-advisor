🪟 Advanced SQL: CTEs, subqueries and window functions

EnglishHinglish

🏠 Real-life example

When a teacher writes each student's class rank on their report card, no student is removed from the register: everyone keeps their own row, with an extra column showing where they stand in their section. A SQL window function does exactly that: it calculates ranks, running totals or previous values across a group without collapsing the rows.

💡 In simple words

Real interview and warehouse queries rarely fit in one flat SELECT. A CTE ('WITH step_name AS (...)') lets you break a complex question into named, readable steps. A window function ('OVER (PARTITION BY ... ORDER BY ...)') computes values across related rows while keeping every row intact: use ROW_NUMBER() or DENSE_RANK() for 'top 3 per category', LAG() to compare today with yesterday, and SUM(...) OVER for running totals. Combine a CTE with a window function to solve the classic top-N-per-group interview question cleanly.

🪜 Step by step

  1. Break complex logic into named steps with 'WITH step1 AS (...), step2 AS (...) SELECT ...' instead of deeply nested subqueries.
  2. Add a window with 'OVER (PARTITION BY group_col ORDER BY sort_col)' to compute per-group metrics while keeping every row.
  3. Rank rows within each group: ROW_NUMBER() gives 1,2,3 (no ties); RANK() gives 1,1,3; DENSE_RANK() gives 1,1,2.
  4. Compare across time with LAG(amount, 1) OVER (PARTITION BY store_id ORDER BY date) for day-over-day change, and SUM(amount) OVER (...) for running totals.
  5. Filter on a window result by wrapping the query in a CTE first, then writing 'WHERE rnk <= 3' in the outer SELECT.

🔑 Key terms

CTE (WITH clause)
A named temporary result at the top of a query that keeps complex SQL readable.
PARTITION BY
Splits the window into groups (e.g. per category or per customer) without collapsing rows.
ROW_NUMBER / DENSE_RANK / LAG
Numbers rows 1,2,3…, ranks ties without gaps, or looks at the previous row's value.

👀 See it in action

sql
-- Top 3 products by revenue in each category
WITH ranked AS (
  SELECT category, product_id, revenue,
         DENSE_RANK() OVER (PARTITION BY category ORDER BY revenue DESC) AS rnk
  FROM product_sales
)
SELECT category, product_id, revenue
FROM ranked
WHERE rnk <= 3;

Compute the rank inside a CTE, then filter with WHERE rnk <= 3 in the outer query.

⚠️ Common mistakes to avoid

  • Using 'WHERE id NOT IN (SELECT ...)' when the subquery can contain NULL: if even one NULL is present, NOT IN returns zero rows! Use 'NOT EXISTS' or 'LEFT JOIN ... WHERE ... IS NULL'.
  • Trying to filter a window function directly in WHERE ('WHERE ROW_NUMBER() OVER (...) <= 3'). SQL runs WHERE before window functions; wrap it in a CTE first.

✅ Quick check

How does a window function (OVER (PARTITION BY ...)) differ from GROUP BY?

  1. GROUP BY collapses each group into one row; a window function keeps every row and adds a calculated column
  2. They are identical
  3. GROUP BY keeps every row; a window function deletes rows
Show answer

A. GROUP BY collapses each group into one row; a window function keeps every row and adds a calculated column: GROUP BY reduces N rows in a group to 1 summary row; OVER (...) keeps all N rows and computes across the window.

🙋 Questions learners ask

When should I use ROW_NUMBER vs DENSE_RANK in interviews?

Ask the interviewer how ties should be handled! If they want exactly 3 rows even on ties, use ROW_NUMBER. If tied products should both appear in the top 3 without skipping rank 2, use DENSE_RANK.

Are CTEs slower than subqueries?

In modern databases and warehouses (PostgreSQL, BigQuery, Snowflake), the query planner optimises CTEs just like subqueries, and CTEs are much easier to read and debug.

🎯 Asked in interviews on this topic

Try answering out loud first, then open the model answer.

What are window functions? Explain ROW_NUMBER, RANK and DENSE_RANK.

💬

Window functions calculate something across related rows without collapsing them like GROUP BY does. For example, a running total or each employee's salary rank within their department, using OVER (PARTITION BY department ORDER BY salary DESC). With ties: ROW_NUMBER gives unique numbers 1, 2, 3 even for ties, so add a tie breaker column to make it deterministic. RANK gives ties the same number and then skips, like 1, 1, 3. DENSE_RANK gives ties the same number without gaps, like 1, 1, 2. LAG and LEAD let you compare a row with the previous or next one.

✅

  • Compute over a window of rows, keeping every row
  • PARTITION BY groups, ORDER BY sets order
  • ROW_NUMBER vs RANK vs DENSE_RANK on ties
  • Uses: top N per group, running totals, LAG and LEAD for changes

: Window functions are the core of most data SQL rounds in 2026.

Write a query to get the top 3 products by revenue in each category.

💬

I'd rank products within each category and then filter. First, in a subquery or CTE, compute revenue per product and add DENSE_RANK() OVER (PARTITION BY category ORDER BY revenue DESC) AS rnk. Then select rows WHERE rnk <= 3. I'd say out loud how I handle ties: DENSE_RANK keeps all tied products, which could return more than 3 rows; if they want exactly 3, I'd use ROW_NUMBER with a tie breaker like product ID.

✅

  • CTE to aggregate revenue per product
  • Window rank partitioned by category
  • Filter rank ≤ 3 in the outer query (you can't filter a window function in WHERE directly)
  • State how ties are handled

: A classic SQL task. Explaining tie handling shows maturity.

What is a CTE (WITH clause) in SQL, and why can NOT IN with NULL values silently return zero rows?

💬

A CTE, or Common Table Expression, is a named temporary result written with WITH at the top of a query. It makes complex SQL readable by breaking it into step by step blocks instead of deeply nested subqueries. For the NULL trap: in SQL, NULL means unknown, so comparing anything to NULL gives UNKNOWN. Because x NOT IN (1, 2, NULL) means x != 1 AND x != 2 AND x != NULL, the whole condition becomes UNKNOWN and returns zero rows whenever the subquery has even one NULL. I use NOT EXISTS or a LEFT JOIN ... WHERE right.id IS NULL instead.

✅

  • CTE = named step with WITH; cleaner than nested subqueries
  • NULL = unknown, so != NULL is never TRUE
  • NOT IN with any NULL returns 0 rows
  • Safe alternatives: NOT EXISTS or LEFT JOIN ... IS NULL

: Tests whether you write readable SQL and know real world NULL bugs.

📌 Remember

Use WITH (CTEs) to write step by step, and OVER (PARTITION BY ... ORDER BY ...) to rank or compare rows without losing detail.
