⚡ Production Python: async/await, Pydantic and testing

EnglishHinglish

🏠 Real-life example

At a busy darshini cafe, the cashier doesn't stand idle in front of the dosa tawa for three minutes before taking the next order. While five dosas cook in parallel, they take more orders. That's async/await. And before the kitchen starts cooking, the token slip checks that the item name and quantity are valid. That's Pydantic.

💡 In simple words

AI services spend most of their time waiting on network calls to LLM APIs and databases. With 'async def' and 'await', Python can run dozens of API requests concurrently instead of waiting for each one in a slow queue. When data arrives from users or an LLM, Pydantic models validate field names and types immediately so bad data fails fast with a clear message. Pair this with a virtual environment (venv) to isolate package versions and pytest to test your logic automatically.

🪜 Step by step

  1. Create an isolated environment for every project: 'python -m venv .venv' and activate it before installing packages.
  2. Define a Pydantic BaseModel for request inputs and LLM structured outputs so wrong types or missing fields fail immediately.
  3. Use 'async def' and 'await' with an async client (AsyncOpenAI, AsyncAnthropic, httpx.AsyncClient) for network calls.
  4. Bound concurrency with 'asyncio.Semaphore(10)' inside 'asyncio.gather' so you run 10 requests at a time without hitting rate limits.
  5. Write unit tests in 'tests/test_app.py' using pytest and run 'pytest' before every commit.

🔑 Key terms

async / await
Lets Python handle other tasks while waiting for slow network or disk calls.
Pydantic BaseModel
A class that checks and converts input data against declared types.
pytest
Python's standard testing tool: write small functions with 'assert' to verify behaviour.

👀 See it in action

python
import asyncio
from pydantic import BaseModel, Field

class Ticket(BaseModel):
    order_id: int
    urgency: str = Field(pattern="^(low|medium|high)$")

async def classify_all(items, call_llm):
    raw = await asyncio.gather(*(call_llm(x) for x in items))
    return [Ticket.model_validate(r) for r in raw]

Call the LLM for many items in parallel, then validate every response with Pydantic.

⚠️ Common mistakes to avoid

  • Calling blocking code like 'time.sleep()' or 'requests.get()' inside an 'async def' function, which freezes the whole event loop. Use 'await asyncio.sleep()' and 'httpx.AsyncClient'.
  • Trusting raw dictionaries from 'json.loads()' on LLM output without validating field types and ranges with Pydantic.

✅ Quick check

You need to call an LLM API for 20 independent documents. What makes it finish ~10× faster?

  1. Running async calls concurrently with asyncio.gather (within rate limits)
  2. Renaming variables to single letters
  3. A normal for loop with time.sleep()
Show answer

A. Running async calls concurrently with asyncio.gather (within rate limits): LLM calls are network-bound: running them concurrently overlaps the waiting time instead of adding it up.

🙋 Questions learners ask

When does async/await help, and when does it not?

It helps for I/O-bound work: waiting on APIs, databases or files. For heavy CPU or matrix maths, use NumPy/PyTorch or multiprocessing instead.

What's the difference between Python type hints and Pydantic?

Standard type hints (x: int) are only checked by editors before running. Pydantic actually validates and converts real data at runtime when your app is running.

How do you get reliable JSON output from an LLM?

💬

First, use the provider's structured output or JSON mode with a schema, which constrains the model to valid JSON. Second, keep the schema simple, with clear field descriptions and allowed values, and set temperature low. Third, always validate in code, for example with Pydantic: check types, required fields and ranges. If validation fails, retry once with the error message, and if it still fails, fall back safely, like marking the item for manual review, rather than crashing. And I log the failures to improve the prompt.

✅

  • Native structured output or JSON mode with a schema
  • Simple schema, clear descriptions, low temperature
  • Validate with code (e.g. Pydantic)
  • Retry with the error, then a safe fallback

: Production reliability, very common in AI product engineer interviews.

Why do production Python AI services use async/await and Pydantic, and how do you test them without paying for live LLM calls?

💬

LLM and vector DB calls spend 99% of their time waiting on network I/O. With synchronous Python, 50 concurrent requests block 50 threads; with async/await and asyncio.gather (bounded by an asyncio.Semaphore for rate limits), one worker handles dozens of waiting requests concurrently. Pydantic enforces strict types and field constraints at the boundary—both on incoming FastAPI requests and on structured JSON returned by an LLM. To test fast and free in CI, I inject the LLM client and mock it in pytest for deterministic unit tests, while running a separate golden eval suite against the real model before release.

✅

  • async/await + asyncio.gather avoids blocking threads on network I/O
  • Bound concurrency with asyncio.Semaphore to respect provider rate limits
  • Pydantic validates both API inputs and LLM structured outputs at runtime
  • pytest with mocked LLM clients for fast CI + golden eval suite for model quality

: Standard backend craft check for AI Product, Agent and Forward Deployed Engineers.

How do you build a reliable multimodal pipeline for messy scanned PDFs or real-time voice?

💬

For messy PDFs and invoices with multi-column tables or handwriting, plain OCR loses layout and misreads numbers. I render pages at 150–200 DPI, pass both the page image and extracted text into a Vision-Language Model with a strict Pydantic JSON schema, and run deterministic code checks afterwards—such as verifying that line-item amounts actually sum to the invoice total—routing mismatches to human review. For voice AI, chaining STT → LLM → TTS must stay under ~800 ms, so I stream partial transcripts on speech pauses, stream LLM sentences into TTS chunk by chunk, and support barge-in so the audio stops the instant the user speaks.

✅

  • Hybrid vision + OCR input with a strict JSON schema for documents
  • Deterministic validation (e.g., line items sum to total) + human review queue
  • Voice AI: streaming STT → LLM → TTS or native speech-to-speech under 800 ms
  • Handle barge-in interruption and redact PII in images/audio

: Multimodal document and voice pipelines are a major 2026 hiring focus.

📌 Remember

async overlaps waiting, Pydantic validates inputs and LLM outputs, and pytest keeps changes safe.
