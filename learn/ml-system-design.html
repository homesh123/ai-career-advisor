🏛️ ML system design: recommendations, search and fraud at scale

EnglishHinglish

🏠 Real-life example

Think of hiring for a popular job role that gets 10,000 applications. You cannot interview all 10,000 people for an hour each. Instead, you run a fast two-stage funnel: first a quick 5-second resume screen narrows 10,000 down to 100 candidates (retrieval), and then a thorough interview ranks the top 10 (ranking). Almost every large-scale ML system — YouTube, Amazon, Swiggy, ads, search — uses this exact two-stage design.

💡 In simple words

In ML system design interviews, never jump straight to 'I'll use a neural network'. Follow a clear 6-step structure: (1) Clarify requirements: business goal, scale, latency budget (e.g. 100 ms), and constraints. (2) Frame the ML task and choose both offline metrics (AUC, Precision@K, NDCG) and online business metrics (CTR, conversion, fraud loss). (3) Data & features: user, item and context features, served from an offline + online feature store. (4) Architecture: for millions of items, use two-stage candidate generation (fast embedding ANN search) + ranking (rich GBDT or deep model); for fraud/moderation, use a fast cascade (rules → lightweight model → heavy model). (5) Serving: batch vs real-time, caching, fallbacks. (6) Monitoring: drift, shadow rollout, A/B testing and feedback loops.

🎬 See how it works

Two-stage funnel: fast candidate retrieval narrows 10 million items to 300 in milliseconds, so the heavy ranking model can score those 300 within the 100 ms budget.

🪜 Step by step

  1. Step 1 — Clarify (3–5 min): ask about scale (users, items, QPS), latency SLA (e.g. p99 < 150 ms), how labels are collected, and business constraints.
  2. Step 2 — Frame & Metrics (5 min): translate the business goal into an ML objective (binary classification, ranking, regression) and pair an offline metric (PR-AUC, NDCG@10) with an online metric (CTR, conversion, fraud loss rate).
  3. Step 3 — Data & Features (8 min): list user, item, interaction and real-time context features; explain how an offline + online feature store prevents training-serving skew.
  4. Step 4 — Model & Funnel (10 min): start with a simple baseline, then design a multi-stage funnel (candidate generation → ranking → re-ranking/business rules).
  5. Step 5 — Serving, Cold Start & Monitoring (10 min): cover caching, fallback when the model times out, cold start for new users/items, shadow deployment, A/B testing and drift alerts.

🔑 Key terms

Two-stage retrieve & rank
Stage 1 fetches ~200 candidates in milliseconds from millions; Stage 2 scores those 200 with a rich ranking model.
Offline vs online metrics
Offline metrics (AUC, NDCG) score held-out test data; online metrics (CTR, revenue, retention) measure real user impact in an A/B test.
Cold start
Serving good predictions for brand-new users or new products with no interaction history, using content features or popular defaults.

  2. Feature fetch (20 ms):        online feature store (user + item + session features)

Each stage shrinks the item count while spending more compute per item.

⚠️ Common mistakes to avoid

  • Spending 30 minutes drawing transformer layers while ignoring data pipelines, labels, latency budgets, cold start and online evaluation.
  • Treating user clicks as unbiased ground truth: items shown at position #1 get clicked more simply because they are at the top (position bias).

✅ Quick check

In an ML system design interview for a 10-million-item recommender, why can't you score every item with your heavy ranking model on each request?

  1. Users prefer random items
  2. Scoring 10 million items per request would violate the ~100 ms latency budget and cost far too much compute
  3. Ranking models can only score 2 items
Show answer

B. Scoring 10 million items per request would violate the ~100 ms latency budget and cost far too much compute: A two-stage funnel uses fast retrieval (ANN/BM25) to narrow 10M items to a few hundred, so the heavy ranker easily finishes under 100 ms.

🙋 Questions learners ask

How do you handle position bias in search and recommendation training data?

Include the display position as a feature during training and set it to a constant (like position 1) at serving time, or weight training examples using Inverse Propensity Scoring (IPS).

What is a Two-Tower model in recommendation systems?

One neural network ('user tower') turns user features into a vector, and a second network ('item tower') turns item features into a vector in the same space. Item vectors are precomputed in a vector index so finding the top 200 items for any user takes milliseconds.

How do you structure an end-to-end ML system design interview, such as feed ranking or search?

💬

I use a six step structure. First, clarify the business objective, latency budget (say 150 ms) and scale. Second, frame the ML task and choose offline metrics (like Recall@100 and NDCG@10) plus online north-star and guardrail metrics. Third, describe the data and feature store: user history, item metadata, and real-time session signals joined point-in-time without leakage. Fourth, use a two-stage funnel: fast candidate generation (two-tower embeddings + BM25 narrowing millions of items to 500) followed by a rich GBDT or neural ranker scoring those 500, plus a re-ranker for diversity and business rules. Fifth, cover cold start and position bias. Sixth, cover shadow/A-B rollout and drift monitoring.

✅

  • Clarify business goal, scale and latency budget first
  • Offline ranking metrics (Recall@K, NDCG) vs online business & guardrail metrics
  • Two-stage architecture: fast candidate retrieval → feature-rich ranker → business rules
  • Address cold start, position bias, point-in-time features and monitoring

: Tests whether you can design a complete production ML funnel rather than just talking about a loss function.

Design a recommendation system for an e commerce site with 2 million products.

💬

Clarify: where recommendations appear, the goal (clicks, purchases), latency budget and data available. Use two stages. Candidate generation: quickly narrow 2 million products to a few hundred, using collaborative filtering or two tower embeddings plus simple sources like popular in category. Ranking: a more detailed model, like gradient boosting or a neural ranker, scores candidates using user, product and context features, then business rules handle stock and diversity. Cold start: new users get popular and contextual items; new products use content features like category and text embeddings. Evaluate offline with recall and NDCG, then online with an A/B test on purchases. Serve with precomputed embeddings and a feature store for fresh features.

✅

  • Clarify goal and latency
  • Two stage: candidate generation, then ranking
  • Cold start for users and items
  • Offline metrics, then A/B test; serving with feature store

: Classic ML system design.

Design a real time fraud detection system with a 150 ms latency budget.

💬

Clarify the cost of missed fraud versus false declines, and the review team's capacity. Features: real time features like the number of transactions from this card in the last 10 minutes, computed from a stream, plus historical features from a feature store; accept that some features are slightly stale to meet latency. Model: gradient boosting, fast and strong on tabular data, with a threshold chosen for the business trade off, and a middle band sent to manual review. Serving: a low latency service with features cached in memory or Redis, and a fallback rule if the model is slow. Labels arrive late through chargebacks, so monitor drift and retrain regularly, and keep rules for brand new fraud patterns.

✅

  • Clarify costs of each error type
  • Streaming plus stored features; staleness trade off
  • Fast model, threshold with review band
  • Low latency serving with fallback; delayed labels, drift, retraining

: Latency, features and business trade offs together.

📌 Remember

Clarify scale & latency → offline + online metrics → features → retrieve then rank → serve with fallbacks → monitor drift.
