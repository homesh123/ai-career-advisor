🟦 TypeScript for AI products: Next.js routes, the AI SDK and keys on the server

EnglishHinglish

🏠 Real-life example

A restaurant keeps the gas cylinder and the cash box in the kitchen, never on the customer's table. The customer only sees the menu and the food. In an AI web app, the API key and the model calls live on the server (the kitchen); the browser (the table) only sends the question and shows the answer.

💡 In simple words

Many AI product engineers ship in TypeScript because the product is a web app. A typical stack: Next.js (React) for the UI and API route handlers, the Vercel AI SDK or the provider's official SDK for model calls, Zod for schemas, a Postgres database (often with pgvector for embeddings), and a queue for slow jobs. Rules that keep it safe and fast: never call the model from the browser with your secret key; put the key in a server environment variable and call the model from a route handler or server action. Authenticate the user and rate limit each route, because every request costs money. Stream long answers; move slow work (indexing documents, batch summaries) to a background job instead of making the user wait. Keep one small "ai" module that wraps model calls so you can log tokens, cost and latency in one place and swap models later. Python is still worth knowing for data and evals, but you don't need to switch your whole product to Python to build great AI features.

🎬 See how it works

The browser only talks to your server. The route checks the user, limits requests and validates input, then one wrapper calls the model and logs cost. Slow work goes to a queue.

🪜 Step by step

  1. Create a Next.js app, add the AI SDK and a provider package, and put the API key in a server environment variable (never one prefixed for the browser, such as NEXT_PUBLIC_).
  2. Write one route handler per AI feature that authenticates the user, rate limits, validates the body with Zod and calls the model.
  3. Put every model call behind one wrapper module that logs task, user, tokens, cost, latency and the prompt version.
  4. Store chats, documents and embeddings in Postgres (pgvector) with user and tenant IDs on every row.
  5. Move slow work such as indexing uploads or nightly summaries to a queue and worker; show progress in the UI.
  6. Deploy with preview environments so every pull request gets a live link to test the AI feature and run evals.

🔑 Key terms

Route handler
A server function (for example app/api/chat/route.ts) that receives requests and calls the model.
Server-only secret
An API key stored in a server environment variable, never sent to the browser.
Background job
Work done outside the request, through a queue, so users don't wait.
Model wrapper
One module that every model call goes through, for logging, cost and swapping models.

👀 See it in action

typescript
// lib/ai.ts: every model call goes through here
export async function callModel(opts: CallOpts) {
  const started = Date.now();
  const res = await generateText({ model: pickModel(opts.task), ...opts });
  await logUsage({
    task: opts.task, userId: opts.userId,
    inputTokens: res.usage.inputTokens, outputTokens: res.usage.outputTokens,
    ms: Date.now() - started,
  });
  return res;
}

// app/api/summarise/route.ts
export async function POST(req: Request) {
  const user = await requireUser(req);          // auth first
  await rateLimit(user.id, { perMinute: 10 });  // every call costs money
  const { text } = Body.parse(await req.json()); // Zod validates input
  return Response.json(await callModel({ task: "summarise", userId: user.id, prompt: text }));
}

Auth, rate limit, validate input, then call the model through one wrapper that logs usage.

⚠️ Common mistakes to avoid

  • Exposing the API key through a NEXT_PUBLIC_ variable or a client component. Anyone can copy it and run up your bill.
  • No auth or rate limit on AI routes, so bots and loops call the model thousands of times.
  • Doing a 40 second indexing job inside the request, which times out on serverless platforms.

✅ Quick check

Where should the call to the LLM API, with your secret key, happen in a Next.js app?

  1. In a React component in the browser, so it feels faster
  2. In a server route handler or server action, with the key in a server environment variable
  3. In the browser, with the key hidden in a minified file
Show answer

B. In a server route handler or server action, with the key in a server environment variable: Anything sent to the browser can be read, minified or not. Keys stay on the server, and the server also enforces auth and limits.

🙋 Questions learners ask

TypeScript or Python for AI product work?

Use the language of your product for the app and API; TypeScript is common for web products. Learn enough Python for notebooks, data checks and eval scripts, where Python has the most tools.

Do I need a framework like LangChain?

Not to start. Provider SDKs plus a small wrapper cover most product features. Add a framework when it clearly saves work, such as complex agents or many retrievers.
