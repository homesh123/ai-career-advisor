🧲 Embeddings and vector databases: searching by meaning

EnglishHinglish

🏠 Real-life example

In a library, books on similar topics sit near each other. Cricket books are next to sports biographies, far from cookbooks. Embeddings give every piece of text a 'location' (a vector) so that similar meanings land close together. Then 'How do I return a damaged item?' sits right next to 'Refund policy for broken products', even with no shared words.

💡 In simple words

An embedding model turns text, or images, into a vector of hundreds of numbers that captures meaning. Similar meanings give vectors close together, measured with cosine similarity. A vector database (pgvector, Pinecone, Qdrant and others) stores millions of these vectors and quickly finds the nearest ones to a query. This is semantic search: searching by meaning, not exact keywords. It powers RAG, recommendations and duplicate detection. Combining it with keyword search (hybrid search) often works best for names and codes.

🎬 See how it works

Each text becomes a point. Similar meanings land close together, so the question finds the refund article even though they share no keywords.

🪜 Step by step

  1. Send text to an embedding model; you get back a vector of hundreds of numbers.
  2. Do this for every document chunk and store the vectors, with the text and metadata, in a vector database.
  3. At search time, embed the user's query the same way.
  4. Find the nearest vectors with cosine similarity; the vector database does this quickly even for millions.
  5. Return the matching chunks, optionally filtered by metadata (department, date, permissions).

🔑 Key terms

Embedding
A vector of numbers representing the meaning of text.
Cosine similarity
How close two vectors point. Near 1 means very similar.
Vector database
A database built to find the nearest vectors fast.

⚠️ Common mistakes to avoid

  • Mixing embedding models. Vectors from different models aren't comparable; re-embed everything when you switch.
  • Relying only on vector search for exact codes, names or IDs. Add keyword search (hybrid).

🙋 Questions learners ask

Do I need a special vector database?

Not always. For small projects, pgvector in PostgreSQL or even an in memory library works. Dedicated databases help at large scale.

Do embeddings work for Hindi?

Multilingual embedding models do, and can even match a Hindi question to an English document. Test with your own examples.

What are embeddings, and what are they used for?

💬

An embedding is a list of numbers that represents the meaning of a piece of text, an image or an item. Things with similar meaning get vectors that are close together. So "how do I reset my password" and "forgot login" end up near each other even though they share no words. We use embeddings for semantic search, RAG, recommendations, clustering and finding duplicates. They're stored in a vector database, which can quickly find the nearest vectors using cosine similarity.

✅

  • Numbers that capture meaning; similar meaning = close vectors
  • Uses: semantic search, RAG, recommendations, dedup
  • Similarity measured with cosine; stored in a vector index

: Core building block for any LLM role.

Explain RAG. Why would you use it?

💬

RAG means retrieval augmented generation. It's like an open book exam for the LLM. First, we index our documents: split them into chunks, turn each chunk into an embedding and store it in a vector database. When a user asks a question, we embed the question, retrieve the most relevant chunks, put them into the prompt with an instruction like "answer only from these sources and cite them", and the LLM writes the answer. We use it because the model doesn't know our private or recent data, and RAG gives grounded answers with sources, without retraining the model.

✅

  • Two phases: indexing and answering
  • Embed, retrieve, put into prompt, generate with citations
  • Why: private and fresh data, fewer hallucinations, no retraining
  • Mention that retrieval quality decides answer quality

: The most asked LLM question of 2026. Be ready for deep follow ups.

How do you choose a chunking strategy for RAG?

💬

Chunks should be big enough to hold a complete idea, but small enough to be precise. I start by respecting the document's structure: split by headings, sections or paragraphs instead of every fixed number of characters, so a table or a step list isn't cut in half. A typical starting size is a few hundred tokens with a small overlap. I attach metadata like title, section and date to each chunk, which helps filtering and citations. Then I test different sizes against an evaluation set of real questions, and keep whatever gives the best retrieval recall.

✅

  • Structure aware splitting (headings, paragraphs, tables)
  • Starting size plus overlap; tune by evals
  • Metadata on each chunk
  • Measure with retrieval recall on real questions

: Practical RAG experience versus tutorial knowledge.

What are hybrid search and reranking, and why do they help?

💬

Vector search is good at meaning but can miss exact terms like product codes, names or error numbers. Keyword search, like BM25, is great at exact terms but misses paraphrases. Hybrid search runs both and merges the results, so you get the best of each. Reranking is a second step: take the top 50 or so candidates and let a more accurate, slower model, a cross encoder, score each one against the question, then keep the best 5. Together they usually give a big jump in retrieval quality for little extra effort.

✅

  • Vector = meaning; keyword = exact terms
  • Hybrid merges both result lists
  • Reranker rescores a shortlist more accurately
  • Trade off: a bit more latency for much better precision

How do you keep a vector index in sync when source documents are updated or deleted?

💬

Treat the index like any other derived dataset. Give each chunk a stable ID based on the document ID and position, and store a hash of the content. A sync job, triggered by change events or on a schedule, finds new, changed and deleted documents; for changed ones it re embeds only chunks whose hash changed and upserts them; for deleted ones it removes their chunks, so the bot never cites removed content. I also keep the embedding model version on each vector, because changing models means re embedding everything.

✅

  • Stable chunk IDs and content hashes
  • Incremental upserts; delete propagation
  • Change data capture or scheduled sync
  • Track embedding model version

How would you build a chatbot that answers students' questions from college notices and PDFs?

💬

I'd use RAG. First, collect the notices and PDFs, extract their text, split it into chunks of a few paragraphs, create embeddings and store them in a vector database. When a student asks a question, embed the question, find the most similar chunks, and send them to an LLM with the instruction to answer only from them and to show which notice the answer came from. If nothing relevant is found, it should say so and point to the office. I'd test it with 30 real student questions, fix the failures, deploy it with Streamlit, and add a feedback button.

✅

  • RAG: ingest, chunk, embed, store
  • Retrieve and answer with citations
  • "I don't know" when there's no answer
  • Test set, deployment, feedback

Design a chatbot that answers employee questions from 50,000 internal documents.

💬

Clarify first: who are the users, which document types, how often they change, required latency, and who can see what. Ingestion: connectors to each source, text extraction, structure aware chunking, embeddings, and a vector store with metadata and permissions. Query: rewrite the question if it's part of a conversation, hybrid search filtered by the user's permissions, rerank, and send the top chunks to the LLM with instructions to cite and say when it doesn't know. Quality: an eval set of real employee questions, measuring retrieval recall and answer faithfulness. Operations: logging, feedback buttons, cost and latency monitoring, and incremental re indexing when documents change.

✅

  • Clarifying questions first
  • Ingestion: connectors, chunking, embeddings, metadata, permissions
  • Query: rewrite, hybrid search, permission filter, rerank, grounded generation with citations
  • Evals, feedback, monitoring, index freshness

: The most common LLM system design question.

Design a recommendation system for an e commerce site with 2 million products.

💬

Clarify: where recommendations appear, the goal (clicks, purchases), latency budget and data available. Use two stages. Candidate generation: quickly narrow 2 million products to a few hundred, using collaborative filtering or two tower embeddings plus simple sources like popular in category. Ranking: a more detailed model, like gradient boosting or a neural ranker, scores candidates using user, product and context features, then business rules handle stock and diversity. Cold start: new users get popular and contextual items; new products use content features like category and text embeddings. Evaluate offline with recall and NDCG, then online with an A/B test on purchases. Serve with precomputed embeddings and a feature store for fresh features.

✅

  • Clarify goal and latency
  • Two stage: candidate generation, then ranking
  • Cold start for users and items
  • Offline metrics, then A/B test; serving with feature store

: Classic ML system design.
