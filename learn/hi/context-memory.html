🧠 Context engineering aur memory: prompt mein kya jaaye, aur kya yaad rakhein

EnglishHinglish

🏠 Asli zindagi ki misaal

Doctor se milne se pehle nurse ek page ki summary deti hai: naam, allergies, aaj ki takleef aur pichhli visit ke notes. Doctor janam se aapki poori file dobara nahi padhta. Context engineering har call pe model ke liye wahi ek page tayyar karna hai: sirf jo abhi chahiye, saaf order mein.

💡 Aasaan shabdon mein

Model calls ke beech kuch yaad nahi rakhta; aapka app har baar sab kuch dobara bhejta hai. Isliye har request hisson se banti hai: system prompt (role, rules, format), user aur account ki baatein (naam, plan, bhasha), retrieve kiye documents, tool results, haal ki conversation, aur naya sawaal. Context engineering in hisson ko token budget ke andar chunna aur sahi order mein rakhna hai. Lambi chats bina hadd ke badhti hain, isliye aakhri kuch turns jaise ke taise rakho aur purane turns ki jagah ek chhoti chalti hui summary rakho. Long term memory ka matlab hai user ki batayi pakki baatein ("mujhe Hindi pasand hai", "meri dukaan Pune mein hai") database mein save karna, user ki permission aur unhe dekhne aur delete karne ke tarike ke saath, phir aage ke prompts mein relevant baatein jodna. Har user ki memory aur documents bilkul alag rakho: user aur tenant ke hisaab se filter code mein karo, model se poochh kar kabhi nahi. Zyaada context hamesha behtar nahi: bekaar text kharch aur latency badhata hai aur jawaab ko confuse kar sakta hai (lost in the middle). Pakke instructions pehle rakho (isse prompt caching mein bhi madad milti hai) aur sawaal aakhir mein.

🎬 Dekho kaise kaam karta hai

Har call token budget ke andar hisson se prompt dobara banati hai: pehle rules, phir baatein, memories aur documents, purane turns ki summary, haal ke turns, aur sawaal aakhir mein.

🪜 Step by step

  1. Apne feature ke saare context sources likho: rules, user ki baatein, memories, documents, tool results, haal ke turns, aur sawaal.
  2. Har source ka token budget rakho (jaise rules 800, documents 3,000, history 1,500) aur sabse kam kaam ke hisse pehle kaato.
  3. Order: pakke instructions pehle, phir facts aur documents, phir haal ke turns, aur sawaal aakhir mein.
  4. Chat limit paar kare to purane turns summarise karo aur chat badhne ke saath summary update rakho.
  5. Long term memories sirf permission se save karo, users ko dikhao kya yaad rakha hai, aur unhe edit ya delete karne do.
  6. Har database aur vector query mein user aur tenant filters lagao, aur test karo ki user A kabhi user B ka data na dekh sake.

🔑 Zaroori shabd

Context engineering
Token budget ke andar har model call mein kya jaaye, use chunna aur order karna.
Running summary
Chhoti summary jo purane chat turns ki jagah leti hai taaki lambi chats chhoti rahein.
Long term memory
User ki pakki baatein jo database mein save hoti hain aur aage ke prompts mein judti hain, permission ke saath.
Tenant isolation
Har customer ka data alag rakhna, code ke filters se pakka karke.

👀 Example dekho

python
def build_context(user, chat, question, budget=6000):
    parts = [SYSTEM_PROMPT]                                   # stable rules first (cacheable)
    parts.append(f"User: {user.name}, plan={user.plan}, language={user.lang}")
    parts += [m.text for m in memories.relevant(user.id, question, k=3)]  # filtered by user_id in code
    parts += [d.text for d in search(question, tenant=user.tenant, k=5)]
    older, recent = chat[:-6], chat[-6:]
    if older:
        parts.append("Earlier in this chat: " + summarise(older))  # running summary
    parts += [f"{m.role}: {m.text}" for m in recent]
    parts.append(f"user: {question}")                         # question last
    return trim_to_budget(parts, budget)

Har call dobara banti hai: rules, user ki baatein, memories, documents, purane turns ki summary, haal ke turns, phir sawaal.

⚠️ Aam galtiyaan jinse bachna hai

  • Poori chat history hamesha bhejte rehna. Har message ke saath kharch aur latency badhti hai aur quality girti hai.
  • Code mein filter karne ki jagah model se kehna "sirf is user ke documents use karo". Prompt access control nahi hai.
  • Bina poochhe sensitive baatein (health, paisa, passwords) yaad rakhna, ya unhe delete karne ka tareeka na dena.

✅ Jaldi se check karo

Aapki support chat jitni lambi chalti hai utni slow aur mehngi hoti jaati hai. Sabse accha fix kya hai?

  1. Aakhri kuch turns jaise hain waise rakho aur purane turns ki jagah chhoti chalti hui summary rakho
  2. Bade context window wala model le lo
  3. History delete kar do taaki har message naye sire se shuru ho
Jawaab dekho

A. Aakhri kuch turns jaise hain waise rakho aur purane turns ki jagah chhoti chalti hui summary rakho: Summary pehle ki zaroori baatein bachaati hai aur prompt chhota rehta hai, to kharch aur latency badhna ruk jaata hai. History delete karne se follow-up sawaal toot jaate hain.

🙋 Seekhne wale yeh poochhte hain

Kya 10 lakh token ka context window yeh sab chhodne ke liye kaafi nahi?

Zyaada fit hota hai, par har token ka paisa aur time phir bhi lagta hai, aur models lamba context kam bharose se use karte hain. Sahi context chunna ab bhi sasta aur zyaada sahi hai.

Memory RAG se kaise alag hai?

RAG shared knowledge laata hai jaise help articles. Memory ek user ke baare mein baatein rakhti hai. Dono prompt mein judte hain, par memory ko permission, editing aur sakht per-user isolation chahiye.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

💬

Model calls ke beech kuch yaad nahi rakhta, isliye main har request pe token budget ke andar context dobara banata hoon. Pakke instructions pehle, phir user ki baatein, relevant long term memories aur retrieve kiye documents, phir haal ki conversation, aur naya sawaal aakhir mein. Aakhri kuch turns jaise ke taise rakhta hoon aur purane turns ki jagah chalti hui summary, taaki kharch aur latency badhti na rahe. Long term memory user ki batayi pakki baatein rakhti hai, sirf permission se, aur users unhe dekh aur delete kar sakte hain. Har memory aur document query code mein user aur tenant se filter hoti hai, model se poochh kar kabhi nahi, aur main test karta hoon ki ek user kabhi doosre ka data na dekh sake.

✅

  • Har call pe budget ke andar context dobara banana
  • Order: rules, baatein, memories, documents, haal ke turns, sawaal
  • Purane turns ke liye chalti hui summary
  • Memory ke liye permission, dikhana aur delete karna
  • User aur tenant isolation code mein

: Chat products andar se asal mein kaise kaam karte hain, iski samajh.

📌 Yaad rakho

Model kuch yaad nahi rakhta: har call pe chhota, sahi order wala context banao, purane turns summarise karo, aur har user ka data code mein alag rakho.
