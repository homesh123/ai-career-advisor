🧪 AI ko evaluate karna: kaise pata chale ki sach mein kaam karta hai

EnglishHinglish

🏠 Asli zindagi ki misaal

Restaurant nayi dish ko sirf chef ki raay se judge nahi karta. Woh bahut saari plates pe ek fixed checklist (taste, temperature, presentation) ke saath tasting sessions karte hain. Evals AI ke tasting sessions hain: asli sawaalon ka fixed set, saaf scoring ke saath, jo har baar prompt ya model badalne pe chalaaya jaata hai.

💡 Aasaan shabdon mein

LLM outputs badalte rehte hain, isliye 'demo mein accha laga' koi saboot nahi hai. Eval set banao: 30 se kuch sau tak asli inputs, expected answers ya grading rules ke saath. Jahan ho sake automatically score karo (exact match, sahi citation hai ya nahi, valid JSON), open-ended quality ke liye clear rubric ke saath LLM-as-judge use karo, aur haath se bhi spot-check karo. Har change pe score track karo, AI ke unit tests ki tarah. Agents ke liye task success rate, steps aur cost naapo. Evals hi production AI engineers ko demo banaane walon se alag karte hain.

🪜 Step by step

  1. Likho aapke feature ke liye accha ka matlab kya hai, acche aur bure outputs ke examples ke saath.
  2. 50 se 200 asli inputs ikattha karo: common cases, edge cases aur purane failures.
  3. Har ek ko score karne ka tarika chuno: jahan ho sake code checks (valid JSON, sahi category), open answers ke liye rubric.
  4. Rubric ke liye LLM judge tabhi use karo jab sample pe check kar lo ki woh human ratings se sehmat hai.
  5. Har prompt ya model change pe eval chalao, waqt ke saath score track karo, aur har naya production failure set mein jodo.

🔑 Zaroori shabd

Eval set
Test inputs ka fixed collection, expected results ke saath.
LLM-as-judge
Rubric ke saath ek LLM se doosre model ke jawaab grade karwana.
Regression
Yahan: aisa change jo pehle ke acche jawaabon ko kharab kar de.

👀 Example dekho

text
Eval set: 50 real HR questions
Check 1: answer cites a source            → 47/50 ✅
Check 2: judge rubric 'correct & complete' → 42/50
Check 3: says 'not found' when it should   → 5/6
Prompt v2 → v3: 42 → 46 correct. Ship v3 🚀

Change ship hoga ya nahi, yeh feeling nahi, numbers decide karte hain.

⚠️ Aam galtiyaan jinse bachna hai

  • Haath se kuch prompts try karke test karna ('vibe checks'). Jo aapne try karne ka socha nahi woh regressions chhoot jaate hain.
  • Sirf aasaan examples wala eval set. Mushkil aur adversarial wale bhi daalo.

✅ Jaldi se check karo

Aapne prompt badla aur jo kuch jawaab try kiye woh behtar lag rahe hain. Aage kya?

  1. Turant ship karo
  2. Model se poochho ki behtar hua ya nahi
  3. Poora eval set chalao aur scores compare karo
Jawaab dekho

C. Poora eval set chalao aur scores compare karo: Kuch examples doosri jagah ke regressions chhupa sakte hain. Eval set asli asar dikhaata hai.

🙋 Seekhne wale yeh poochhte hain

Kitne examples chahiye?

50 acche examples se shuru karo; inse hi zyaadatar regressions pakad mein aa jaate hain. Waqt ke saath har important category ke liye sainkdon tak badhao.

Online evals kya hain?

Launch ke baad asli usage ke signals: thumbs up ya down, AI output mein edits, insaanon tak escalations, task completion.

Users kehte hain RAG bot galat jawaab deta hai, jabki sahi document maujood hai. Kaise debug karoge?

💬

Main step by step dhoondhunga chain kahan tooti. Ek: kya document index hua bhi tha? Ingestion logs dekho. Do: kya woh retrieve hua? Query chala ke dekho sahi chunk top results mein hai ya nahi; nahi hai to retrieval problem hai, jaise galat chunking, koi filter use hata raha hai, ya query ke shabd document se alag hain. Teen: kya retrieve hua par context limit ki wajah se kat gaya? Chaar: kya prompt mein tha, par model ne ignore ya galat padha? Yeh prompt ya model problem hai. Main is case ko evaluation set mein jodunga aur retrieval aur generation alag alag naapunga, taaki sahi hissa theek ho aur problem wapas na aaye.

✅

  • Failure classify karo: index nahi hua, retrieve nahi hua, neeche rank hua, kat gaya, ya model ne galat use kiya
  • Har stage logs aur traces se dekho
  • Fix stage pe depend: chunking, hybrid search, reranking, prompt changes
  • Case eval set mein jodo; retrieval aur generation alag naapo

: Structured debugging. Step by step classification hi top jawaab karte hain.

Complex PDFs aur tables pe production RAG pipeline ko kaise evaluate aur improve karte ho?

💬

Main retrieval metrics ko generation metrics se alag rakhta hoon. Retrieval ke liye main golden question-to-source-chunk dataset pe Recall@k aur MRR track karta hoon; generation ke liye faithfulness (bina saboot ka ek bhi daawa nahi) aur answer relevance naapta hoon. Complex PDFs aksar isliye fail hote hain kyunki naive character chunking tables ko beech se kaat deti hai aur section headers kho deti hai. Main ise layout-aware parsing se theek karta hoon jo tables ko Markdown mein saabit rakhti hai, embed karne se pehle har chunk ke aage document title aur section breadcrumb jodti hai, BM25 + dense vectors ko Reciprocal Rank Fusion se milaati hai, aur top 5 chunks chunne ke liye cross-encoder reranker lagati hai.

✅

  • Retrieval (Recall@k, MRR) ko generation faithfulness se alag evaluate karo
  • Layout-aware parsing jo Markdown tables saabit rakhe aur section headers aage jode
  • Hybrid search (BM25 + dense embeddings) Reciprocal Rank Fusion (RRF) se juda
  • Cross-encoder reranking + multi-turn chats ke liye query rewriting

: Dekhta hai ki aapne 20-line tutorial se aage asli RAG banaya hai ya nahi.

LLM product mein hallucinations kaise kam karoge?

💬

Kai layers mein. Model ko RAG se ground karo aur bolo sirf diye gaye sources se jawaab de, aur sources mein jawaab na ho to "mujhe nahi pata" kahe. Citations maango, taaki users aur code check kar sakein. Factual kaam ke liye temperature kam rakho. Jahan ho sake code se output validate karo, jaise check karna ki quote kiya number source mein hai. High risk cases mein low confidence jawaab insaan ko bhejo. Aur eval set se hallucination rate naapo, taaki har prompt ya model change check ho.

✅

  • Retrieval se grounding aur "pata nahi" ka rule
  • Citations aur automated checks
  • Kam temperature, structured output
  • Risky cases ke liye human review; evals se rate track karo

: Zimmedaar engineering; har LLM role mein poochha jaata hai.

LLM application ko evaluate kaise karte ho?

💬

Pehle task ke liye "accha" kya hai woh define karta hoon, phir asli examples ka evaluation set banata hoon, shuru mein 50 se 200, jisme common cases, edge cases aur pehle ke failures hon. Har ek ke liye score karne ka tarika tay karta hoon: jahan ho sake code se exact checks, jaise valid JSON ya sahi category; open jawaabon ke liye rubric jo insaan ya LLM judge score kare, jise maine human ratings se check kiya ho. RAG mein retrieval aur answer quality alag naapta hoon. Yeh suite har prompt ya model change pe unit tests ki tarah chalata hoon, aur asli usage bhi dekhta hoon: thumbs down, edits aur escalations.

✅

  • Pehle "accha" define karo, phir asli cases se dataset
  • Jahan ho sake code checks; jahan zaroori rubric aur LLM judge
  • RAG mein retrieval aur generation ke alag metrics
  • Har change pe chalao; users ke online signals jodo

Kya LLM judge pe bharosa kar sakte hain?

💬

Thoda, agar calibrate karo. LLM judges ke known biases hain: lambe jawaab, pehla option aur apna style pasand karte hain, aur scores run to run badal sakte hain. Isliye judge ko examples ke saath saaf rubric deta hoon, score se pehle reason maangta hoon, sample pe human ratings se compare karta hoon jab tak acchi agreement na ho, do jawaab compare karte waqt order badalta hoon, aur judge model fixed rakhta hoon. Jahan result code se check ho sake, jaise sahi calculation ya database ki sahi state, wahan judge ke bajaye wahi use karta hoon.

✅

  • Known biases: length, position, self preference, variance
  • Rubric, reasoning, humans se calibration
  • Jahan ho sake executable checks

: Barikiyan; evals wale sawaal ka common follow up.

Agent ko test aur evaluate kaise karte ho?

💬

Teen levels pe. Unit level: har tool aur tool calls ki parsing normal code tests se. Step level: ek situation mein kya agent sahi tool sahi arguments ke saath chunta hai? Inke decisions ka dataset bana ke score karta hoon. End to end: sandbox mein fake ya test systems ke saath poore tasks chalao aur final state check karo, jaise "sahi refund bana, aur kuch nahi?". Har task ke steps, cost aur time bhi track karta hoon, aur failure cases test karta hoon: tools ke errors, aur aise prompts jo use galat kaam karwaane ki koshish karein.

✅

  • Tools ke unit tests
  • Step level decision evals
  • Sandbox mein end to end tasks, final state check
  • Steps, cost, latency track; errors aur attacks test

: Agent specific evaluation ki gehraai.

LLM applications chalaana classic ML models se kaise alag hai?

💬

Kai nayi cheezein sambhaalni padti hain. Prompts code hain, to unhe versioning, review aur testing chahiye. Har prompt ya model change pe evaluation suites chalni chahiye, kyunki ek accuracy number nahi hota. Cost per request aur per feature monitor karni padti hai, kyunki tokens ke saath badhti hai. Providers models update karte hain, to versions pin karta hoon aur upgrade se pehle evals dobara chalata hoon. Chain ya agent ke har step ki logging aur tracing debugging ke liye zaroori hai. Aur safety checks: prompt injection, logs mein personal data, aur content filters.

✅

  • Prompt versioning aur testing
  • Release gates ke roop mein eval suites
  • Token cost monitoring
  • Model version pinning, tracing, safety controls

Customer ke saamne aapka AI demo fail ho gaya. Kya karoge?

💬

Shaant raho aur imaandaar: "Yeh galat jawaab hai, chaliye dikhata hoon kyun hua." Phir use use karo: trace kholo, dikhao kaunsa document retrieve hua aur kahan galat hua, aur samjhao evaluation set se ise kaise pakdenge aur theek karenge. Customers un logon pe zyaada bharosa karte hain jo apne system ki galtiyaan samajhte hain, bajaye unke jo dikhaate hain ki koi galti nahi hoti. Baad mein case eval set mein jodo, theek karo, aur result ke saath follow up karo. Agli baar unke asli data se rehearse karo aur ek recorded backup rakho.

✅

  • Shaant raho, maano
  • Ise control dikhaane mein badlo: trace, samjhao, fix ka plan
  • Fix ke saath follow up
  • Bachaav: asli data se rehearse, backup recording

: Pressure mein sanyam aur imaandaari.

AI feature ke success metrics kaise define karoge?

💬

Layers mein, taaki koi ek number problems na chhupaaye. Model quality: eval set pe accuracy, hallucination rate ya rubric scores. User outcome: kya madad mili? Task completion, bacha time, users AI output kitna edit karte hain. Adoption aur engagement: kitne eligible users try karte hain aur wapas aate hain. Business: revenue, per ticket cost ya retention. Saath mein guardrail metrics jo bigadne nahi chahiye, jaise complaints, latency aur per use cost. Bahut accurate feature jo koi use na kare woh bhi fail hai, aur popular feature jiska error rate zyaada ho woh risk hai.

✅

  • Layers: model quality, user outcome, adoption, business
  • Guardrails: errors, latency, cost, complaints
  • Leading vs lagging metrics
  • Koi metric akela nahi

Kaise pata chalega ki aapka AI feature launch ke layak hai?

💬

Banane se pehle team ke saath "accha" define karta hoon: expected outputs ke saath asli examples ka set aur scoring rubric, aksar har important category ke 100 ya zyaada, asli tickets ya documents se. Launch thresholds tay karte hain, jaise common cases pe 90% sahi aur safety cases pe zero critical errors, aur current baseline, aksar insaanon, se compare karte hain. Phir asli users ke saath limited beta, layered metrics track karte hain, aur jab offline evals aur asli usage dono bar paar karein tab bada launch. Launch ke baad bhi har change pe evals chalte rehte hain.

✅

  • Banane se pehle accha define: eval set aur rubric
  • Launch thresholds, zero tolerance categories samet
  • Current baseline se compare
  • Asli users ke saath beta, phir bada launch; evals chalte rehte hain

Students ke sawaalon ka jawaab college notices aur PDFs se dene wala chatbot kaise banaoge?

💬

Main RAG use karunga. Pehle notices aur PDFs ikattha karo, text nikaalo, kuch paragraphs ke chunks mein todo, embeddings banao aur vector database mein rakho. Student sawaal poochhe to sawaal ka embedding banao, sabse milte julte chunks dhoondho, aur LLM ko bhejo is instruction ke saath ki sirf unhi se jawaab de aur bataaye kis notice se aaya. Kuch relevant na mile to saaf bole aur office ka raasta bataaye. 30 asli student sawaalon se test karta, failures theek karta, Streamlit se deploy karta, aur feedback button jodta.

✅

  • RAG: ingest, chunk, embed, store
  • Retrieve karo aur citations ke saath jawaab
  • Jawaab na ho to "pata nahi"
  • Test set, deployment, feedback

Ek chatbot design karo jo 50,000 internal documents se employees ke sawaalon ke jawaab de.

💬

Pehle clarify: users kaun hain, kaunse document types, kitni baar badalte hain, zaroori latency, aur kaun kya dekh sakta hai. Ingestion: har source ke connectors, text extraction, structure ke hisaab se chunking, embeddings, aur metadata aur permissions ke saath vector store. Query: baatcheet ka hissa ho to sawaal rewrite karo, user ki permissions se filter kiya hybrid search, rerank, aur top chunks LLM ko is instruction ke saath ki cite kare aur na pata ho to bataaye. Quality: asli employee sawaalon ka eval set, retrieval recall aur answer faithfulness naapo. Operations: logging, feedback buttons, cost aur latency monitoring, aur documents badlein to incremental reindexing.

✅

  • Pehle clarifying sawaal
  • Ingestion: connectors, chunking, embeddings, metadata, permissions
  • Query: rewrite, hybrid search, permission filter, rerank, citations ke saath grounded jawaab
  • Evals, feedback, monitoring, index freshness

Humne AI tutor launch kiya. 10% se kam users ko pasand hai, zyaadatar ko bekaar lagta hai. Kya karoge?

💬

Pehle batwaara samjho. Woh 10% kaun hain: kaunsi class, subject ya use case? Aur baaki ke liye "bekaar" ka matlab kya: galat jawaab, bahut generic, bahut slow, ya jo chahiye tha woh nahi? Main asli conversations padhunga, dekhunga users kahan chhodte hain, aur dono groups se baat karunga. Agar 10% ka ek saaf use case hai, jaise maths ki exam revision, to wahan double down: us case ki quality evals se sudhaaro, aur onboarding badlo taaki naye users usi se shuru karein. Baaki ke liye top failure wajahein theek karo ya jin segments mein fit nahi wahan feature dikhaana band karo.

✅

  • Pasand karne wale vs baaki ko alag karo
  • Conversations, funnels, interviews se diagnose
  • Jo use case chal raha hai uspe double down
  • Top failures theek karo ya audience chhoti karo

Team chat app ke liye AI "is thread ka summary do" feature design karo.

💬

Clarify: thread kitna lamba, bhashaayein, latency target aur privacy rules. Flow: user summarise dabaaye to backend woh messages laaye jo user dekh sakta hai, bahut lambe threads ko kaate ya chunks banaaye, aur LLM ko prompt bheje jo decisions, khule sawaal aur owners ke saath action items structured format mein maange. Result "draft" label aur source messages ke links ke saath UI mein stream karo. Summaries cache karo aur naye messages aane pe incremental update. Asli threads ke set se evaluate karo, chhoote decisions aur gadhe hue facts ke liye score. Usage, thumbs down aur per summary cost track karo.

✅

  • Constraints clarify
  • Permission ke hisaab se messages, lambe threads ki chunking
  • Structured prompt; source links ke saath streaming UI
  • Caching, evals, metrics
