📂 Files, JSON, APIs aur error handling

EnglishHinglish

🏠 Asli zindagi ki misaal

Jab aap Swiggy pe khana order karte ho, kabhi restaurant busy hota hai ya ek second ke liye internet chala jaata hai. App blank screen dekar crash nahi hota: woh problem pakadta hai, thoda ruk kar retry karta hai, ya saaf message dikhata hai. Python mein files padhte ya APIs call karte waqt try/except aur retries yahi kaam karte hain.

💡 Aasaan shabdon mein

Asli AI programs files se data padhte hain aur web APIs se baat karte hain. 'with open(...) as f:' use karo taaki kuch gadbad hone par bhi file apne aap close ho jaaye. APIs aur config files aksar JSON use karti hain, jise Python ka json module dictionaries aur lists mein badal deta hai. Kyunki file gayab ho sakti hai, JSON toot sakta hai aur APIs pe rate limit (HTTP 429) lag sakti hai, isliye risky calls ko 'try / except' mein rakho taaki expected errors sambhal sakein, failure log ho, aur temporary network errors pe exponential backoff ke saath retry ho.

🪜 Step by step

  1. Files ko 'with open("data.json", "r", encoding="utf-8") as f:' se kholo taaki Python file apne aap band kar de.
  2. json.load(f), json.loads(text) aur json.dumps(data, indent=2) se JSON padho aur likho.
  3. API keys ko .env file se environment variables (os.environ["API_KEY"]) mein padho, code mein kabhi mat likho.
  4. External I/O (file padhna, HTTP calls, JSON parsing) ko json.JSONDecodeError ya httpx.TimeoutException jaise specific errors ke liye try / except mein rakho.
  5. Temporary failures (HTTP 429 rate limit ya 503 overload) ko exponential backoff (1s, 2s, 4s + thoda random jitter) aur max retry limit ke saath retry karo.

🔑 Zaroori shabd

Context manager (with)
File ya connection kholta hai aur block khatam hote hi apne aap band kar deta hai.
try / except
Aisa code chalata hai jo fail ho sakta hai aur crash hone ke bajaye specific errors pakadta hai.
Exponential backoff
Jab API overloaded ho to retries ke beech 1s, phir 2s, phir 4s rukna.

👀 Example dekho

python
import json, time

with open("orders.json") as f:
    orders = json.load(f)

def call_with_retry(fn, retries=3):
    for attempt in range(retries):
        try:
            return fn()
        except TimeoutError:
            if attempt == retries - 1:
                raise
            time.sleep(2 ** attempt)   # 1s, 2s, 4s

'with' se JSON safely padho, aur temporary timeouts ko exponential backoff ke saath retry karo.

⚠️ Aam galtiyaan jinse bachna hai

  • Khaali 'except:' likhna jo har error chupke se daba de, variable naam ki galti bhi. Hamesha specific exceptions pakdo aur log karo.
  • HTTP 400 (galat request) ya 401 (galat API key) jaise permanent errors ko retry karna. Sirf 429, 502, 503 ya timeouts jaise temporary errors retry karo.

✅ Jaldi se check karo

Sirf 'f = open(...)' ke bajaye 'with open(...) as f:' se file kyun kholni chahiye?

  1. Block ke andar error aane par bhi Python file apne aap band kar deta hai
  2. Isse file chhoti ho jaati hai
  3. Yeh sirf JSON files ke liye kaam karta hai
Jawaab dekho

A. Block ke andar error aane par bhi Python file apne aap band kar deta hai: 'with' block yeh pakka karta hai ki block khatam hote hi ya error aate hi file saaf tareeke se close ho jaaye.

🙋 Seekhne wale yeh poochhte hain

Exponential backoff mein random jitter kyun jodte hain?

Agar 100 workers ek hi second pe rate limit hit karein aur sab theek 2 second rukein, to sab phir ek saath server se takrayenge. Chhota random delay retries ko phaila deta hai.

JSON Lines (.jsonl) kya hai aur AI mein kyun use hota hai?

Aisi file jismein har line ek valid JSON object hoti hai. Aap 10 GB ki badi file ek saath memory mein laaye bina line-by-line padh sakte ho, jo training aur eval datasets ke liye best hai.

Python mein files safely kaise padhte ho, external API kaise call karte ho, aur rate limits ya network errors kaise sambhaalte ho?

💬

Files ke liye main hamesha with open(..., encoding='utf-8') block use karta hoon taaki exception aane pe bhi file apne aap band ho, aur bade datasets ko JSON Lines (.jsonl) se ek baar mein ek line stream karta hoon. API calls ke liye main hamesha explicit timeout deta hoon taaki atka hua server mere worker ko freeze na kare, HTTP status code check karta hoon, aur khaali except ke bajaye TimeoutError ya HTTPError jaise specific exceptions pakadta hoon. Jab LLM API 429 (rate limit) ya 503 de, to main exponential backoff aur random jitter ke saath kuch baar retry karta hoon taaki saare workers ek hi second pe retry na maarein.

✅

  • Files ke liye with context manager aur bade data ke liye .jsonl use karo
  • HTTP / LLM API calls pe hamesha explicit timeout lagao
  • Khaali except nahi, specific exceptions pakdo
  • 429 / 5xx errors ko exponential backoff aur jitter ke saath retry karo

: Har AI engineer roz APIs call karta hai aur files padhta hai; interviewers production aadatein dekhte hain.

AI project mein Git aur pull requests kaise use karte ho, aur kya kabhi commit nahi karna chahiye?

💬

Main main branch ko hamesha deployable rakhta hoon aur saara kaam chhoti feature branches pe karta hoon. Har commit ek chhota, logical badlaav hota hai saaf message ke saath ki kyun kiya. Pull request kholne se pehle main locally tests aur linters chalata hoon, aur PR description mein kya badla, kaise test kiya, aur AI badlaavon ke liye pehle aur baad ke evaluation scores likhta hoon. Main API keys, .env files, customer data, bade datasets ya model weights kabhi Git mein commit nahi karta; woh .gitignore mein jaate hain, secrets environment variables ya secret manager mein rehte hain, aur bade artifacts object storage ya model registry mein.

✅

  • Feature branches, chhote commits, eval results ke saath saaf PR descriptions
  • .env secrets, raw customer data ya bade model files kabhi commit mat karo
  • .gitignore, secret managers aur artifact storage use karo
  • Code aur prompt changes dono ko ek hi discipline se review karo

: Production repo ke paas bhejne se pehle basic software engineering safai check karta hai.
