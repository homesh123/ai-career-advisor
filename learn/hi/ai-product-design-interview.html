🏗️ AI product system design: AI feature ko shuru se aakhir tak design karna

EnglishHinglish

🏠 Asli zindagi ki misaal

Ghar design karne ko kaha gaya architect kitchen ki tiles se shuru nahi karta. Woh poochhta hai kaun rahega, budget kitna hai aur plot kitna bada hai, kamron aur unke beech aane jaane ka sketch banata hai, phir plumbing, safety aur monsoon mein kya hoga uski baat karta hai. AI design interview isi order ko inaam deta hai: pehle users aur goal, phir flow, phir mushkil hisse aur aapko kaise pata chalega ki kaam kar raha hai.

💡 Aasaan shabdon mein

Is round mein aapko ek prompt milta hai jaise "Ek AI assistant design karo jo hamare help centre se customers ke sawaalon ka jawaab de" aur 45 minute. Ek structure jo kaam karta hai: (1) Clarify: users kaun hain, unhe kaunsa kaam karwaana hai, scale (users, documents, bhashaayein), aur success numbers mein kya hai. Poocho ki AI zaroori bhi hai ya nahi. (2) User experience: feature kahan dikhega, intezaar ke dauraan user kya dekhega, woh kaise verify aur sudhaarega, aur failure ka raasta. (3) Architecture: client, API, model wrapper, retrieval (ingestion, chunking, hybrid search, reranking), tools, storage, aur background jobs; boxes aur arrows banao. (4) Model aur prompt choices wajah ke saath: kis step ke liye kaunsa model, jahan code result use karta hai wahan structured output. (5) Quality: offline eval set, launch criteria, online signals aur feedback loop. (6) Production: har step ka latency budget, cost per request, caching, rate limits, fallbacks, privacy, permissions aur prompt injection. (7) Rollout aur iteration: canary, A/B test, version do mein kya banaoge. Trade-offs mein baat karo ("chhota model 70% kharch bachaata hai; agar evals 2 points ke andar rahein to main use lunga") aur interviewer ke saath time check karte raho.

🎬 Dekho kaise kaam karta hai

AI design round ka 45 minute plan: clarify, user experience, architecture, model choices, quality, production ki limits, phir rollout. Numbers ke saath trade-offs mein baat karo.

🪜 Step by step

  1. Pehle 5 minute clarifying questions pe lagao: users, karne wala kaam, scale, bhashaayein, constraints aur success metric.
  2. User flow batao: entry point, kya stream hota hai, users kaise verify aur sudhaarte hain, aur failure ka raasta.
  3. Architecture banao: client, API, model wrapper, retrieval pipeline, tools, storage, queue; ek request ko usmein se guzaar ke dikhao.
  4. Har step ke liye model wajah ke saath chuno, aur batao kahan structured output aur kahan streaming use karoge.
  5. Quality samjhao: eval set, launch criteria, online signals, feedback loop.
  6. Production cover karo: latency budget, cost per request, caching, limits, fallbacks, privacy, permissions aur prompt injection.
  7. Rollout aur version do ke plan ke saath khatam karo, aur apne main trade-offs ek minute mein summarise karo.

🔑 Zaroori shabd

Clarifying questions
Users, scale aur success ke baare mein sawaal jo poora design tay karte hain.
Latency budget
Allowed response time ko steps mein baantna (retrieval 150 ms, model 1.5 s…).
Launch criteria
Release se pehle poore hone wale eval aur safety thresholds.
Trade-off
Har choice ke saath kya milta hai aur kya chhodna padta hai, yeh batana.

👀 Example dekho

text
Design: "Ask our help centre" assistant (45 min plan)
 0-5   Clarify   B2C app, 2M users, 1,800 articles, EN+Hindi, goal: −20% support tickets
 5-10  UX        chat in Help tab · streams · cites articles · 👍👎 · "talk to a human"
10-22  Design    ingest (nightly + on publish) → chunk by heading → embed → hybrid search
                 query → rewrite (small model) → retrieve 30 → rerank 5 → answer (large model)
22-30  Quality   200 golden Qs, faithfulness ≥ 0.9, refusal when no source, Hindi set
30-38  Prod      p95 < 3 s · ₹0.30/answer · cache per locale · injection filter · PII redaction
38-45  Rollout   5% canary → A/B on ticket rate · v2: account-aware answers via tools

Time ke hisaab se plan structure dikhata hai: clarify, UX, architecture, quality, production, rollout.

⚠️ Aam galtiyaan jinse bachna hai

  • User aur goal samjhe bina seedha model ka naam aur vector database pe kood jaana.
  • Evaluation pe ek shabd nahi. "Aapko kaise pata chalega ki kaam karta hai?" interviewers ke liye sabse zaroori sawaal hai.
  • Cost aur latency ko nazarandaaz karna, ya koi numbers hi na dena.

✅ Jaldi se check karo

Interviewer kehta hai "Ek AI feature design karo jo lambi customer calls ko summarise kare." Sabse pehle kya karna chahiye?

  1. Sabse accha model chuno aur uske benchmark scores samjhao
  2. Har service ke saath poora architecture banao
  3. Poocho summaries kaun padhta hai, unse kya karta hai, calls kitni aur kis bhasha mein hain, aur success ka matlab kya hai
Jawaab dekho

C. Poocho summaries kaun padhta hai, unse kya karta hai, calls kitni aur kis bhasha mein hain, aur success ka matlab kya hai: Requirements baaki sab tay karti hain: supervisor ke quality review ki summary CRM fields bharne wali summary se bahut alag hai. Pehle clarify karna product sense dikhata hai.

🙋 Seekhne wale yeh poochhte hain

Model ke andar ki baaton mein kitna gehra jaana chahiye?

Product roles ke liye utna hi jitna decisions pe asar daale: context limits, latency, cost, formats ki reliability. Time UX, quality aur trade-offs pe lagao.

Is round ki practice kaise karein?

10 rozmarra ke AI features chuno (email reply drafts, meeting notes, search, shopping assistant), 45 minute ka timer lagao, 7 hisse bol kar samjhao aur diagram banao. Is lesson se milaan karo.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

Team chat app ke liye AI "is thread ka summary do" feature design karo.

💬

Clarify: thread kitna lamba, bhashaayein, latency target aur privacy rules. Flow: user summarise dabaaye to backend woh messages laaye jo user dekh sakta hai, bahut lambe threads ko kaate ya chunks banaaye, aur LLM ko prompt bheje jo decisions, khule sawaal aur owners ke saath action items structured format mein maange. Result "draft" label aur source messages ke links ke saath UI mein stream karo. Summaries cache karo aur naye messages aane pe incremental update. Asli threads ke set se evaluate karo, chhoote decisions aur gadhe hue facts ke liye score. Usage, thumbs down aur per summary cost track karo.

✅

  • Constraints clarify
  • Permission ke hisaab se messages, lambe threads ki chunking
  • Structured prompt; source links ke saath streaming UI
  • Caching, evals, metrics
