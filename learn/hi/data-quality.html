🧹 Data quality: kharab data jaldi pakadna

EnglishHinglish

🏠 Asli zindagi ki misaal

Achha restaurant sabziyaan kitchen tak pahunchne se pehle hi back door pe check karta hai. Wahan pakde gaye sade tamatar ka koi nuksaan nahi; customer ki plate pe pakde gaye to restaurant ki izzat ka nuksaan. Data quality checks data ke liye wahi back-door inspection hain.

💡 Aasaan shabdon mein

Kharab data chupchaap models aur dashboards tod deta hai. Pipeline ke har stage pe data automatically check karo: completeness (unexpected nulls nahi), validity (umar 0 se 120 ke beech, sahi email format), uniqueness (duplicate order IDs nahi), consistency (totals unke line items se match karein), aur freshness (data time pe aaya). Great Expectations ya dbt tests jaise tools in rules ko code mein likhte hain, aur rule tootne pe pipeline fail karte hain ya alert bhejte hain. ML ke liye label quality aur class balance bhi check karo, aur upstream teams ke saath data contract rakho, taaki schema changes achanak pareshaan na karein.

🪜 Step by step

  1. Schema check karo: expected columns aur types aaye.
  2. Volume check karo: row counts haal ke dino ke mukaable normal range mein.
  3. Values check karo: required fields mein NULL nahi, values allowed range mein, unique keys sach mein unique.
  4. Freshness check karo: sabse naya data kaafi recent hai.
  5. Fail hone pe kya hoga tay karo: critical issues pe pipeline roko, chhote pe alert, aur data use karne walon ko batao.

🔑 Zaroori shabd

Validation rule
Check jo data ko pass karna hi hai, jaise amount ≥ 0.
Freshness
Data utna naya hai ya nahi jitna hona chahiye.
Data contract
Data bhejne aur use karne wali teams ke beech schema aur quality ka agreement.

👀 Example dekho

yaml
# dbt tests on the orders model
models:
  - name: fact_orders
    columns:
      - name: order_id
        tests: [unique, not_null]
      - name: amount
        tests:
          - dbt_utils.accepted_range: { min_value: 0 }
      - name: status
        tests:
          - accepted_values: { values: ['placed', 'delivered', 'cancelled'] }

Rules data ke saath rehte hain aur har pipeline run pe chalte hain.

⚠️ Aam galtiyaan jinse bachna hai

  • Quality sirf aakhir mein check karna. Problems wahin pakdo jahan data aata hai, failne se pehle.
  • Har data source ka owner nahi, jisse failures teams ke beech ghoomte rehte hain.

🙋 Seekhne wale yeh poochhte hain

Kaunse tools madad karte hain?

dbt tests, Great Expectations, Soda aur warehouse ke built in constraints. Kuch SQL checks se simple shuru karo.

Data contract kya hai?

Data banane wali team aur use karne wali teams ke beech schema, matlab aur quality ka agreement, taaki changes chupke se cheezein na todein.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

Missing values kaise sambhaalte ho?

💬

Pehle poochta hoon value missing kyun hai, kyunki isse fix badalta hai. Agar income isliye missing hai ki logon ne batana nahi chaaha, to missing hona khud ek signal ho sakta hai. Options: bahut kam missing hon to rows hatao; median ya sabse common value se bharo; model ya group average se bharo; ya bhari hui value ke saath "was missing" flag column jodo. XGBoost jaise tree models missing values khud sambhaal lete hain. Jo bhi karo, bharne ka logic sirf training data pe fit karo.

✅

  • Pehle samjho kyun missing hai
  • Hatao, bharo (median, mode, model), ya missing flag jodo
  • Leakage se bachne ke liye imputation sirf train pe fit karo

: Data cleaning ki samajh, sirf ek pandas command nahi.

Click through rate raaton raat 20% gir gaya, par input distributions normal dikhte hain. Model drift hai ya bug?

💬

Achanak raaton raat girna slow drift nahi, bug ya badlaav jaisa lagta hai. Main is order mein check karunga: kya kuch deploy hua, jaise naya model, feature pipeline ya front end change? Kya logging ya metric khud toota hai, jaise clicks record hi nahi ho rahe? Kya features der se ya default values ke saath aa rahe hain, jo aggregate distributions mein na dikhe? Kya saare users mein hai ya ek platform, region ya app version mein? Holdout ya pichhle model se compare karunga. Sab theek nikle tabhi concept drift sochunga, jaise tyohaar ya competitor ka event, aur retrain karunga.

✅

  • Achanak = pehle badlaav ya bug pe shaq
  • Deploys, logging, der se ya default features check karo
  • Platform, region, version se segment karo
  • Phir asli drift socho

: Shaant, systematic incident debugging.

Pipeline aise kaise design karoge ki reruns aur backfills se data double count na ho?

💬

Har step idempotent banao: do baar chalaao to wahi result jo ek baar chalaane pe. Practically, data partition se process karta hoon, jaise ek baar mein ek date, aur us partition ko overwrite ya unique key pe MERGE karke likhta hoon, bina soche append kabhi nahi. Partition tay karne ke liye processing time nahi, data ki event date use karta hoon. Phir pichhle mahine ka backfill bas un dates ko dobara chalaana hai. Run ke baad check jodta hoon ki row counts aur totals source se match karein.

✅

  • Idempotency ki definition
  • Date se partition; partition overwrite ya keys pe MERGE/upsert
  • Event time vs processing time
  • Reconciliation checks

: Reliability ki soch; 2026 ka bada data engineering topic.

Pipeline mein kaunse data quality checks lagaoge?

💬

Boundaries pe checks: jab data aaye aur publish hone se pehle. Schema: expected columns aur types. Completeness: row counts pichhle dino ke mukaable expected range mein, aur zaroori fields NULL nahi. Validity: values allowed range ya list mein, jaise age 0 se 120. Uniqueness: primary keys unique. Freshness: sabse naya data kaafi recent. Consistency: totals source se match. dbt tests ya Great Expectations jaise tools ise aasaan banate hain. Critical failures pipeline rokte hain; chhote waale alert bhejte hain.

✅

  • Schema, volume, nulls, ranges, uniqueness, freshness, reconciliation
  • Ingestion pe aur publish se pehle
  • Critical pe roko, chhote pe alert
  • Tools: dbt tests, Great Expectations

: Kharab data chupke se AI models todta hai; woh bachaav dekhna chahte hain.

Daily sales analytics aur ML demand forecast ko data dene wali pipeline design karo.

💬

Sources: change data capture se order database, product catalogue aur store data. Raw data date se partition karke lake ya warehouse mein lao. dbt se saaf staging tables mein transform, phir orders fact table aur product, store aur date dimensions wala star schema. ML team same models se bani feature table padhti hai, taaki analytics aur ML ek baat bolein. Airflow se orchestrate, har task date se idempotent, layers ke beech data quality tests, aur data der se ya galat ho to alerts. Backfills bas date partitions ke reruns. Lineage aur owners document karo taaki log jaanein numbers kahan se aate hain.

✅

  • Sources aur ingestion (CDC)
  • Raw → staging → modelled layers (star schema)
  • ML ke liye shared feature tables
  • Orchestration, idempotency, quality tests, backfills, lineage

: End to end data architecture.
