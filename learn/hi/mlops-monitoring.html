📡 Models ki monitoring: drift aur chupke se hone wale failures

EnglishHinglish

🏠 Asli zindagi ki misaal

Diwali se pehle train hua demand-forecasting model tyohaar ke season mein achanak bilkul alag shopping patterns dekhta hai. Kuch 'crash' nahi hua, lekin uski predictions ab galat hain. Jaise gaadi ki alignment dheere-dheere bigadti hai, waise hi duniya badalne pe models drift hote hain, aur pata tabhi chalta hai jab aap check karte rehte ho.

💡 Aasaan shabdon mein

Software errors shor machaate hain. Model errors aksar chupchaap hote hain. Data drift matlab inputs badal gaye: naye tarah ke users, naye products, upstream ka koi field badal gaya. Concept drift matlab rishta badal gaya: jo pehle fraud ka signal tha, ab nahi hai. Input distributions, prediction distributions, data quality aur, labels aane pe, asli accuracy monitor karo. LLM apps ke liye har request trace karo (prompt, retrieve hue docs, output, cost, latency) aur user feedback track karo. Alerts aur retraining ya rollback ka plan zaroorat se pehle bana ke rakho.

🎬 Dekho kaise kaam karta hai

Kuch crash nahi hua, lekin tyohaar ke season mein inputs drift ho gaye. Monitoring alert threshold paar hone pe line pakad leti hai, isse pehle ki accuracy chupchaap gir jaaye.

🪜 Step by step

  1. System health: latency, errors aur throughput, alerts ke saath.
  2. Data: live feature distributions ko training data se compare karo (jaise PSI se); missing values aur schema changes pe nazar rakho.
  3. Predictions: har predicted class ka hissa aur confidence scores waqt ke saath dekho.
  4. Asli performance: jab true labels aayein (din ya hafton baad), har hafte accuracy, precision aur recall nikalo.
  5. Action lo: har alert ka ek owner aur ek action ho, jaise pipeline check karo, retrain karo ya rollback karo.

🔑 Zaroori shabd

Data drift
Input data training data se alag dikhne lagta hai.
Concept drift
Model ne jo real-world rishta seekha tha, woh badal gaya.
Tracing
Debugging ke liye har request ke steps, inputs aur outputs record karna.

👀 Example dekho

text
Weekly monitor — fraud model v12
  avg transaction amount   ₹1,240 → ₹2,980   ⚠️ data drift (festival season)
  % flagged as fraud       1.1%  → 4.6%     ⚠️ prediction shift
  confirmed-fraud recall   0.81  → 0.62     🚨 alert → retrain with recent data

Inputs, outputs aur, jab ho sake, asli nateeje dekhte raho.

⚠️ Aam galtiyaan jinse bachna hai

  • Sirf uptime monitor karna. Service chalu ho sakti hai jabki predictions chupke se galat hon.
  • Bahut saare shor wale alerts, jisse log unhe ignore karne lagte hain. Sirf us pe alert karo jis pe action chahiye.

✅ Jaldi se check karo

Bina code change ke mahino mein model accuracy dheere-dheere gir rahi hai. Sabse likely wajah?

  1. Bahut zyaada tests
  2. Syntax error
  3. Drift: real-world data ya rishte badal gaye
Jawaab dekho

C. Drift: real-world data ya rishte badal gaye: Duniya badalti hai to frozen model purana pad jaata hai. Yahi drift hai.

🙋 Seekhne wale yeh poochhte hain

Kitni baar retrain karun?

Jab monitoring drift ya girti performance dikhaye, ya agar data predictable tarah se badalta hai to regular schedule pe. Model badalne se pehle hamesha evaluate karo.

Kaunse tools use hote hain?

System metrics ke liye Prometheus aur Grafana, drift ke liye Evidently ya waisa tool, aur performance reports ke liye aapka warehouse.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

Training serving skew kya hai, aur ise kaise rokte ho?

💬

Jab production mein model ko jo data milta hai woh training wale data se alag tarah se banta hai, aur model chupke se kharab perform karta hai. Jaise training mein "average spend" SQL mein 30 din pe nikala, par live service Python mein 7 din pe nikaal rahi hai. Bachaav: training aur serving dono ke liye ek shared feature pipeline ya feature store, prediction ke time features log karke training data se compare karna, aur aise tests jo same input dono raaston se chalaayein.

✅

  • Definition aur concrete example
  • Wajah: features ke do alag code paths
  • Fix: shared pipeline ya feature store, logging, comparison tests

: Production ML ki maturity.

Data drift aur concept drift mein kya fark hai? Bina labels ke inhe kaise pakadoge?

💬

Data drift tab hai jab inputs badal jaate hain, jaise naya customer segment ya sensor recalibrate hua, par outcome se rishta wahi rehta hai. Concept drift tab hai jab rishta hi badal jaata hai, jaise fraudsters naye tarike apnaate hain, to wahi inputs ab kuch aur matlab rakhte hain. Fresh labels ke bina, main input features ke distributions ko training baseline se PSI ya KS test jaise statistics se compare karta hoon, predictions aur confidence scores ka distribution dekhta hoon, aur complaints ya manual overrides jaise business signals track karta hoon. Labels baad mein aayein to har time window ki asli performance nikaalta hoon.

✅

  • Data drift = inputs badle; concept drift = rishta badla
  • Feature aur prediction distributions monitor karo (PSI, KS)
  • Labels der se aayein to proxy signals
  • Labels aane pe asli performance naapo

: Lagbhag har loop mein MLOps ka core topic.

Production mein model ke liye kya kya monitor karoge?

💬

Chaar layers. System health: latency, error rates, throughput, CPU, GPU aur memory. Data: missing values, schema changes, training ke mukaable feature distributions. Model: prediction distribution, confidence, aur labels aane pe asli accuracy. Business: woh metric jiske liye model bana hai, jaise fraud ka nuksaan ya conversion. Har alert ka ek action ho, jaise "on call ko page karo" ya "retrain karo", warna log alerts ignore karte hain. System metrics ke liye Prometheus aur Grafana, aur data ke liye Evidently jaisa drift tool.

✅

  • System, data, model aur business layers
  • Baseline se comparison
  • Alerts actions se jude
  • Example tools

: Production models ki poori ownership.

Click through rate raaton raat 20% gir gaya, par input distributions normal dikhte hain. Model drift hai ya bug?

💬

Achanak raaton raat girna slow drift nahi, bug ya badlaav jaisa lagta hai. Main is order mein check karunga: kya kuch deploy hua, jaise naya model, feature pipeline ya front end change? Kya logging ya metric khud toota hai, jaise clicks record hi nahi ho rahe? Kya features der se ya default values ke saath aa rahe hain, jo aggregate distributions mein na dikhe? Kya saare users mein hai ya ek platform, region ya app version mein? Holdout ya pichhle model se compare karunga. Sab theek nikle tabhi concept drift sochunga, jaise tyohaar ya competitor ka event, aur retrain karunga.

✅

  • Achanak = pehle badlaav ya bug pe shaq
  • Deploys, logging, der se ya default features check karo
  • Platform, region, version se segment karo
  • Phir asli drift socho

: Shaant, systematic incident debugging.

Machine learning ke liye CI/CD kaisa dikhta hai?

💬

Normal CI/CD jaisa, plus data aur models. CI: har code change pe unit tests, data validation tests aur sample pe chhoti training run taaki errors pakde jaayein. Training pipelines schedule pe ya naya data aane pe chalti hain, parameters aur metrics experiment tracker mein log karti hain, aur model registry mein register karti hain. CD: naya model tabhi promote hota hai jab fixed evaluation set pe current wale ko hara de aur bias aur latency jaise checks paas kare, phir canary ya shadow deployment se dheere rollout, metrics gire to automatic rollback.

✅

  • Code aur data ke tests; chhota training smoke test
  • Tracked, reproducible training aur model registry
  • Fixed evals pe promotion gates
  • Rollback ke saath dheere rollout

: Process ki maturity.

Naya model offline behtar dikha par production ki chinta hai. Safely rollout kaise karoge?

💬

Step by step. Pehle shadow mode: naya model asli traffic pe predictions karta hai, par users ko purane model ka output milta hai, to predictions, latency aur errors safely compare kar sakta hoon. Phir canary: chhota hissa, jaise 5%, traffic naye model ko bhejo aur technical aur business metrics dekho. Theek rahe to dheere badhao, ya proper A/B test chalao. Purana model ready rakho taaki rollback ek switch ho. Success aur rollback criteria shuru karne se pehle tay karo.

✅

  • Shadow deployment
  • Chhote traffic pe canary, phir badhao ya A/B test
  • Pehle se tay success aur rollback criteria
  • Ek click rollback

: Production mein risk management.

LLM applications chalaana classic ML models se kaise alag hai?

💬

Kai nayi cheezein sambhaalni padti hain. Prompts code hain, to unhe versioning, review aur testing chahiye. Har prompt ya model change pe evaluation suites chalni chahiye, kyunki ek accuracy number nahi hota. Cost per request aur per feature monitor karni padti hai, kyunki tokens ke saath badhti hai. Providers models update karte hain, to versions pin karta hoon aur upgrade se pehle evals dobara chalata hoon. Chain ya agent ke har step ki logging aur tracing debugging ke liye zaroori hai. Aur safety checks: prompt injection, logs mein personal data, aur content filters.

✅

  • Prompt versioning aur testing
  • Release gates ke roop mein eval suites
  • Token cost monitoring
  • Model version pinning, tracing, safety controls

: 2026 mein interviews mein LLMOps badh raha hai.

150 ms latency budget wala real time fraud detection system design karo.

💬

Clarify karo miss hue fraud aur galat decline ki keemat kya hai, aur review team kitna sambhaal sakti hai. Features: stream se nikle real time features jaise is card se pichhle 10 minute mein kitni transactions, plus feature store se historical features; latency ke liye kuch features ka thoda purana hona maan lo. Model: gradient boosting, tabular data pe tez aur mazboot, business trade off ke hisaab se threshold, aur beech ki band manual review ko. Serving: kam latency service, features memory ya Redis mein cached, aur model slow ho to fallback rule. Labels chargebacks se der se aate hain, to drift monitor karo aur regularly retrain karo, aur bilkul naye fraud patterns ke liye rules rakho.

✅

  • Har galti ki keemat clarify
  • Streaming plus stored features; staleness trade off
  • Tez model, review band ke saath threshold
  • Fallback ke saath low latency serving; der se labels, drift, retraining

: Latency, features aur business trade offs ek saath.

Kal se aapke AI feature ka response time double ho gaya. Kaise investigate karoge?

💬

Check karo kya badla: deploys, prompt changes, model version change, ya provider ka status issue. Phir traces se dhoondho kaunsa step slow hua: retrieval, LLM call, tool call ya humara code. Agar LLM call hai, to dekho prompts ya outputs lambe hue ya nahi, jaise bada retrieved context ya aisa prompt change jo jawaab lambe karta hai, ya provider ki latency badhi. Agar humara hai, to database queries, cache hit rate aur traffic volume dekho. Wajah theek karo, zaroorat ho to rollback, aur har step pe latency alert jodo taaki agli baar jaldi pakde.

✅

  • Kya badla? deploys, prompts, models, provider
  • Har step ke traces se jagah dhoondho
  • Token count badalna common wajah
  • Theek ya rollback; har step pe alerts
