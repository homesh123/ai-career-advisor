🔎 Production RAG: chunking, hybrid search, reranking aur debugging

EnglishHinglish

🏠 Asli zindagi ki misaal

Medical kitab mein sirf 'matlab' se dhoondhna 'tez bukhaar ka ilaaj' jaise sawaal ke liye badhiya hai, par 'PCM-650mg' jaise exact medicine code ke liye bekaar. Aur agar dose ki table beech se do hisson mein kat gayi, to dono adhure hain. Production RAG dono theek karta hai: documents ko headings aur tables ke hisaab se todta hai (smart chunking), matlab aur exact shabd dono se dhoondhta hai (hybrid search), aur ek dhyaan se padhne wale second reader (reranker) se top 5 hisse chunta hai.

💡 Aasaan shabdon mein

Basic RAG demos production mein teen wajahon se toot-te hain: galat chunking, exact shabd chhootna, aur kachre se bhare top-k results. Pehla, documents ko sections, headings aur tables ke hisaab se todo (~300–600 tokens, 10–15% overlap) aur har chunk pe metadata (title, section, date, permissions) jodo. Doosra, hybrid search lagao: dense vector search (matlab ke liye) aur BM25 keyword search (IDs, codes aur naamo ke liye) ko Reciprocal Rank Fusion se milao. Teesra, jaldi se top 30–50 chunks nikalo, phir cross-encoder reranker se sabse acche 5 chuno. Aakhir mein, retrieval (Recall@k, MRR) ko generation (faithfulness, answer relevance) se alag naapo taaki hamesha pata rahe kaunsa hissa theek karna hai.

🎬 Dekho kaise kaam karta hai

Hybrid search exact shabd matches (BM25) aur matlab matches (vectors) ko milata hai, phir reranker top candidates ko score karke sirf sabse acche 5 chunks LLM ko deta hai.

🪜 Step by step

  1. Documents ko structure ke saath parse karo: headings ko unke paragraphs ke saath rakho, aur tables ko beech se kaatne ke bajaye Markdown ya HTML mein poora rakho.
  2. Har chunk ke saath zaroori metadata jodo: document_id, title, section_path, updated_at, aur permission filter ke liye allowed_roles.
  3. Hybrid retrieval chalao: BM25 keyword search (exact shabd, SKUs, naam) aur vector search (matlab) ko Reciprocal Rank Fusion (RRF) se milao.
  4. Top 30–50 chunks ko cross-encoder reranker (jaise BGE-Reranker ya Cohere Rerank) se score karo aur sirf top 5–8 LLM ko bhejo.
  5. 50 sawaalon ke golden set pe retrieval aur generation alag naapo: retrieval ke liye Recall@5 aur MRR, aur jawaab ke liye faithfulness/groundedness.

🔑 Zaroori shabd

Hybrid search (BM25 + vectors)
Keyword search (exact shabd aur codes ke liye) ko embedding search (matlab ke liye) ke saath milana.
Cross-encoder reranker
Doosre stage ka model jo sawaal aur candidate chunk ko ek saath padhkar exact relevance score karta hai.
Recall@k vs Faithfulness
Recall@k dekhta hai ki sahi chunk top k mein aaya ya nahi; faithfulness dekhta hai ki LLM ne bina man-ghadant baat jode unhi chunks se jawaab diya ya nahi.

👀 Example dekho

text
Query: "Refund rule for plan PRO-2026 after 14 days?"
  1. Metadata filter:  doc_type = 'policy' AND user_role IN allowed_roles
  2. Hybrid retrieval: BM25 ('PRO-2026') + Vector ('refund after 14 days') → top 40 chunks
  3. Reranker:         Cross-encoder scores (query, chunk) pairs → top 5 chunks
  4. Generation:       LLM answers ONLY from top 5 chunks + cites [Policy §4.2]

Pehle permissions filter karo, hybrid search se chauda nikalo, reranker se chhanto, phir citations ke saath jawaab banao.

⚠️ Aam galtiyaan jinse bachna hai

  • Galat RAG jawaab aane par yeh dekhe bina ki sahi chunk retrieve bhi hua tha ya nahi, seedha system prompt badalne lagna!
  • LLM prompt mein 30 chunks bhar dena ('lost in the middle'): 5 reranked chunks ke mukaable kharch aur time badh jaata hai aur accuracy gir jaati hai.

✅ Jaldi se check karo

Jab bhi users 'ERR_AUTH_409' jaise exact error codes poochte hain, aapka RAG bot fail ho jaata hai. Sabse asardaar ilaaj kya hai?

  1. Vector search ke saath BM25 keyword search (hybrid search) aur reranker jodo
  2. LLM ka temperature 1.0 kar do
  3. Docs se saare error codes hata do
Jawaab dekho

A. Vector search ke saath BM25 keyword search (hybrid search) aur reranker jodo: Dense embeddings matlab compress karte hain aur exact codes bhula dete hain; BM25 exact tokens pakadta hai aur vectors matlab.

🙋 Seekhne wale yeh poochhte hain

RAG ke bajaye 10-lakh token wale context window mein saare documents kyun na daal dein?

Har sawaal pe 5 lakh tokens bhejne mein har baar bhaari kharch aur 15–30 second lagte hain. RAG 50 ms mein aur 200 guna kam kharch mein zaroori 2,000 tokens nikal laata hai.

RAG mein query rewriting ya HyDE kya hota hai?

Users chhote ya adhure follow-up sawaal likhte hain ('aur contractors ke liye?'). Index mein dhoondhne se pehle ek chhota LLM step chat history dekhkar use poora search query bana deta hai.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

Users kehte hain RAG bot galat jawaab deta hai, jabki sahi document maujood hai. Kaise debug karoge?

💬

Main step by step dhoondhunga chain kahan tooti. Ek: kya document index hua bhi tha? Ingestion logs dekho. Do: kya woh retrieve hua? Query chala ke dekho sahi chunk top results mein hai ya nahi; nahi hai to retrieval problem hai, jaise galat chunking, koi filter use hata raha hai, ya query ke shabd document se alag hain. Teen: kya retrieve hua par context limit ki wajah se kat gaya? Chaar: kya prompt mein tha, par model ne ignore ya galat padha? Yeh prompt ya model problem hai. Main is case ko evaluation set mein jodunga aur retrieval aur generation alag alag naapunga, taaki sahi hissa theek ho aur problem wapas na aaye.

✅

  • Failure classify karo: index nahi hua, retrieve nahi hua, neeche rank hua, kat gaya, ya model ne galat use kiya
  • Har stage logs aur traces se dekho
  • Fix stage pe depend: chunking, hybrid search, reranking, prompt changes
  • Case eval set mein jodo; retrieval aur generation alag naapo

: Structured debugging. Step by step classification hi top jawaab karte hain.

RAG ke liye chunking strategy kaise chunte ho?

💬

Chunks itne bade hon ki poora idea aa jaaye, par itne chhote ki precise rahein. Main document ka structure maanta hoon: har fixed number of characters pe todne ke bajaye headings, sections ya paragraphs se todo, taaki table ya steps ki list beech se na kate. Shuruaat kuch sau tokens aur thode overlap se. Har chunk ke saath title, section aur date jaisa metadata jodta hoon, jo filtering aur citations mein madad karta hai. Phir asli sawaalon ke evaluation set pe alag sizes test karta hoon aur jo sabse accha retrieval recall de woh rakhta hoon.

✅

  • Structure ke hisaab se todo (headings, paragraphs, tables)
  • Starting size plus overlap; evals se tune
  • Har chunk pe metadata
  • Asli sawaalon pe retrieval recall se naapo

: Tutorial knowledge vs practical RAG experience.

Hybrid search aur reranking kya hain, aur kyun madad karte hain?

💬

Vector search matlab samajhne mein accha hai par product codes, naam ya error numbers jaise exact terms miss kar sakta hai. Keyword search, jaise BM25, exact terms mein badhiya hai par alag shabdon mein kahi baat miss karta hai. Hybrid search dono chalata hai aur results milata hai. Reranking doosra step hai: top 50 ke aas paas candidates lo aur ek zyaada accurate, slow model, cross encoder, se har ek ko sawaal ke against score karwao, phir best 5 rakho. Dono milkar thode extra kaam mein retrieval quality kaafi badha dete hain.

✅

  • Vector = matlab; keyword = exact terms
  • Hybrid dono result lists ko milata hai
  • Reranker shortlist ko zyaada accurately score karta hai
  • Trade off: thodi latency, kaafi behtar precision

: Basic RAG se aage ki gehraai.

Complex PDFs aur tables pe production RAG pipeline ko kaise evaluate aur improve karte ho?

💬

Main retrieval metrics ko generation metrics se alag rakhta hoon. Retrieval ke liye main golden question-to-source-chunk dataset pe Recall@k aur MRR track karta hoon; generation ke liye faithfulness (bina saboot ka ek bhi daawa nahi) aur answer relevance naapta hoon. Complex PDFs aksar isliye fail hote hain kyunki naive character chunking tables ko beech se kaat deti hai aur section headers kho deti hai. Main ise layout-aware parsing se theek karta hoon jo tables ko Markdown mein saabit rakhti hai, embed karne se pehle har chunk ke aage document title aur section breadcrumb jodti hai, BM25 + dense vectors ko Reciprocal Rank Fusion se milaati hai, aur top 5 chunks chunne ke liye cross-encoder reranker lagati hai.

✅

  • Retrieval (Recall@k, MRR) ko generation faithfulness se alag evaluate karo
  • Layout-aware parsing jo Markdown tables saabit rakhe aur section headers aage jode
  • Hybrid search (BM25 + dense embeddings) Reciprocal Rank Fusion (RRF) se juda
  • Cross-encoder reranking + multi-turn chats ke liye query rewriting

: Dekhta hai ki aapne 20-line tutorial se aage asli RAG banaya hai ya nahi.

Ek chatbot design karo jo 50,000 internal documents se employees ke sawaalon ke jawaab de.

💬

Pehle clarify: users kaun hain, kaunse document types, kitni baar badalte hain, zaroori latency, aur kaun kya dekh sakta hai. Ingestion: har source ke connectors, text extraction, structure ke hisaab se chunking, embeddings, aur metadata aur permissions ke saath vector store. Query: baatcheet ka hissa ho to sawaal rewrite karo, user ki permissions se filter kiya hybrid search, rerank, aur top chunks LLM ko is instruction ke saath ki cite kare aur na pata ho to bataaye. Quality: asli employee sawaalon ka eval set, retrieval recall aur answer faithfulness naapo. Operations: logging, feedback buttons, cost aur latency monitoring, aur documents badlein to incremental reindexing.

✅

  • Pehle clarifying sawaal
  • Ingestion: connectors, chunking, embeddings, metadata, permissions
  • Query: rewrite, hybrid search, permission filter, rerank, citations ke saath grounded jawaab
  • Evals, feedback, monitoring, index freshness

: Sabse common LLM system design sawaal.

📌 Yaad rakho

Structure se chunk karo, BM25 + vectors se dhoondho, top 50 → top 5 rerank karo, aur retrieval va generation alag naapo.
