🧾 Structured outputs: JSON schemas, validation aur retries

EnglishHinglish

🏠 Asli zindagi ki misaal

Bank form bharte waqt fixed boxes hote hain: naam, PAN, amount. Clerk seedha system mein daal deta hai kyunki har jawaab apne box mein hai. Agar aap khula letter likh dete, to kisi ko padh kar dobara type karna padta. Structured output model se form bharwaata hai, letter nahi likhwaata, taaki aapka code jawaab seedha use kar sake.

💡 Aasaan shabdon mein

Zyaadatar AI product features chat nahi hote: woh email se fields nikaalte hain, ticket classify karte hain, form bharte hain ya UI component ke liye data dete hain. Inke liye aapko schema se match karta JSON chahiye. Schema ek baar code mein banao (TypeScript mein Zod, Python mein Pydantic) aur teen tarah use karo: model ko bhejo (structured output ya tool calling mode, jo zyaadatar providers dete hain), response validate karo, aur apne code ko type karo. Schema mode ke saath bhi validate karo: values galat range mein ho sakti hain, dates banaayi hui ho sakti hain aur enums bhatak sakte hain. Validation fail ho to ek baar error message jodkar retry karo ("total number hona chahiye"), phir safe default ya human review pe jao. Schemas chhote aur flat rakho, har field ka description do, "nahi mila" ke liye null allow karo taaki model values na banaaye, aur categories ke liye enum do. Baad mein business rules plain code mein check karo: totals milte hain, dates future mein nahi hain, IDs database mein hain.

🎬 Dekho kaise kaam karta hai

Model khula text likhne ki jagah schema bharta hai. Aapka code use validate karta hai: sahi data save hota hai, galat jawaab ko error ke saath ek retry milta hai, aur phir bhi galat ho to insaan ke paas jaata hai.

🪜 Step by step

  1. Pehle schema likho (Zod ya Pydantic), har field pe description, categories ke liye enums aur jo values na ho sakein unke liye nullable fields.
  2. Saade shabdon mein JSON maangne ki jagah provider ka structured output ya tool calling mode use karo aur schema do.
  3. Har response ko usi schema se validate karo; fail ho to validation error prompt mein daalkar ek baar retry karo.
  4. Business rules plain code mein check karo: totals milte hain, IDs hain, dates sahi hain. Jo fail ho use human review mein bhejo.
  5. 50 ya zyaada asli inputs ka eval set banao jismein expected fields hon aur har field ki accuracy naapo, sirf "valid JSON" nahi.

🔑 Zaroori shabd

JSON schema
Output mein kaunse fields, types aur allowed values honi chahiye, uska exact description.
Zod / Pydantic
Libraries jo schema ek baar banaati hain aur TypeScript ya Python mein data ko uske against validate karti hain.
Validate and retry
Output check karo; fail ho to error ke saath dobara poocho, phir fallback.
Nullable field
Aisa field jo null ho sakta hai, taaki model guess karne ki jagah "nahi mila" keh sake.

👀 Example dekho

typescript
import { z } from "zod";
import { generateObject } from "ai";

const Ticket = z.object({
  category: z.enum(["billing", "delivery", "technical", "other"]),
  orderId: z.string().regex(/^A\d{5}$/).nullable().describe("null if not mentioned"),
  urgency: z.number().int().min(1).max(5),
  summary: z.string().max(200),
});

const { object } = await generateObject({ model, schema: Ticket, prompt: email });
// object is typed and already validated against the schema
if (object.orderId && !(await orderExists(object.orderId))) object.orderId = null; // business rule in code

Ek hi schema model, validation aur aapke types chalata hai; business rules phir bhi plain code mein check hote hain.

⚠️ Aam galtiyaan jinse bachna hai

  • Free text jawaab se regex se JSON nikaalna. Pehle hi ajeeb reply pe toot jaata hai; schema mode aur validation use karo.
  • Har field required rakhna, jisse model order numbers, dates aur amounts banaane pe majboor hota hai.
  • Ek call mein 60 fields wale bade nested schemas. Behtar accuracy ke liye steps ya chhote schemas mein baanto.

✅ Jaldi se check karo

Ek invoice email mein order number nahi hai. Aapka extraction schema ise kaise sambhaale?

  1. orderId ko nullable rakho, description ke saath "null if not mentioned"
  2. Model se summary ke andar "unknown" likhwao
  3. orderId ko required rakho taaki model hamesha bhare
Jawaab dekho

A. orderId ko nullable rakho, description ke saath "null if not mentioned": Required field model ko value banaane pe majboor karta hai. Null allow karne se use imaandaari se kehne ka raasta milta hai ki data nahi hai.

🙋 Seekhne wale yeh poochhte hain

Structured output ya tool calling?

Jab hamesha ek hi object wapas chahiye to structured output use karo. Jab model ko tay karna ho kaunsa action lena hai, har ek apne schema ke saath, tab tool calling.

Kya valid JSON mein bhi model galat values de sakta hai?

Haan. Sahi shape ka matlab sahi content nahi. Isiliye range checks, business rules aur field level eval set jodte ho.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

Form ya database bharne wale feature ke liye LLM se bharosemand JSON kaise loge?

💬

Main code mein ek schema banata hoon, Zod ya Pydantic se, aur use teen tarah use karta hoon: provider ke structured output ya tool calling mode se model ko deta hoon, har response ko usse validate karta hoon, aur apne code mein type ki tarah use karta hoon. Fields chhote aur description wale rakhta hoon, categories ke liye enums, aur jo value na ho sake us field ko nullable rakhta hoon taaki model use banaaye nahi. Validation fail ho to error message ke saath ek baar retry, phir human review. Uske baad bhi business rules plain code mein check karta hoon, jaise totals milna aur IDs hona, aur asli examples ke set pe har field ki accuracy naapta hoon.

✅

  • Model, validation aur types ke liye ek schema
  • Structured output ya tool calling mode, "JSON mein jawaab do" nahi
  • Banaayi values rokne ke liye nullable fields aur enums
  • Validate, error ke saath ek retry, phir fallback
  • Code mein business rules aur field level eval set

: Kya aap aise AI features bana sakte ho jin pe doosra code bharosa kar sake.

LLM call karne wale code ke liye automated tests kaise likhte ho?

💬

Main code ki sahi hone aur jawaab ki quality ko alag rakhta hoon. Saare model calls ek function se guzarte hain, to unit tests mein use ek nakli se badal deta hoon jo tay responses deta hai, kharab bhi jaise galat JSON, khaali jawaab, timeout ya 429, aur apna parsing, retries aur fallbacks check karta hoon. End to end flows ke liye recorded asli responses fixtures ki tarah replay karta hoon, aur prompt ya model badalne pe dobara record karta hoon. Contract tests check karte hain ki outputs schema se match karein aur prompts mein sirf current user ka data ho. Chhota live smoke test schedule pe chalta hai taaki provider ke badlaav pakde jaayein. Jawaab ki quality eval suite alag se parakhta hai. Pull request suite tez, free aur deterministic rehta hai.

✅

  • Unit tests ke liye nakli model, failure cases ke saath
  • End to end flows ke liye recorded responses
  • Schemas aur data isolation ke liye contract tests
  • Schedule pe live smoke tests
  • Quality ke liye evals, tests se alag

: Non-deterministic systems ke aas paas engineering discipline.

📌 Yaad rakho

Prompt, validation aur types ke liye ek schema; null allow karo, validate karo, ek baar retry, phir fallback.
