🪟 Advanced SQL: CTEs, subqueries aur window functions

EnglishHinglish

🏠 Asli zindagi ki misaal

Jab teacher har student ke report card pe uski class rank likhte hain, to register se kisi student ki row hatayi nahi jaati: sabki apni row rehti hai, bas ek extra column jud jaata hai ki apne section mein unka sthaan kya hai. SQL window function bilkul yahi karta hai: bina rows ko sikoote group ke upar rank, running total ya pichhli value nikalta hai.

💡 Aasaan shabdon mein

Asli interview aur warehouse queries shayad hi ek simple SELECT mein aati hain. CTE ('WITH step_name AS (...)') ek mushkil sawaal ko naam wale, saaf steps mein todne deta hai. Window function ('OVER (PARTITION BY ... ORDER BY ...)') har row ko barkaraar rakhte hue related rows pe calculation karta hai: 'har category ke top 3' ke liye ROW_NUMBER() ya DENSE_RANK() use karo, aaj ko kal se compare karne ke liye LAG(), aur running totals ke liye SUM(...) OVER. Classic top-N-per-group interview sawaal ko saaf tareeke se hal karne ke liye CTE aur window function ko saath lagao.

🪜 Step by step

  1. Gehre nested subqueries ke bajaye 'WITH step1 AS (...), step2 AS (...) SELECT ...' se mushkil logic ko naam wale steps mein todo.
  2. Har row rakhte hue group metrics nikalne ke liye 'OVER (PARTITION BY group_col ORDER BY sort_col)' lagao.
  3. Har group ke andar rows rank karo: ROW_NUMBER() 1,2,3 deta hai (bina tie); RANK() 1,1,3 deta hai; DENSE_RANK() 1,1,2 deta hai.
  4. Day-over-day badlaav ke liye LAG(amount, 1) OVER (PARTITION BY store_id ORDER BY date) aur running totals ke liye SUM(amount) OVER (...) use karo.
  5. Window result pe filter lagane ke liye pehle query ko CTE mein rakho, phir baahar wale SELECT mein 'WHERE rnk <= 3' likho.

🔑 Zaroori shabd

CTE (WITH clause)
Query ke upar ek naam wala temporary result jo mushkil SQL ko padhne mein aasaan rakhta hai.
PARTITION BY
Bina rows ghataaye window ko groups mein baant-ta hai (jaise har category ya har customer).
ROW_NUMBER / DENSE_RANK / LAG
Rows ko 1,2,3… number deta hai, ties ko bina gap ke rank karta hai, ya pichhli row ki value dekhta hai.

👀 Example dekho

sql
-- Top 3 products by revenue in each category
WITH ranked AS (
  SELECT category, product_id, revenue,
         DENSE_RANK() OVER (PARTITION BY category ORDER BY revenue DESC) AS rnk
  FROM product_sales
)
SELECT category, product_id, revenue
FROM ranked
WHERE rnk <= 3;

CTE ke andar rank nikalo, phir baahar wali query mein WHERE rnk <= 3 se filter karo.

⚠️ Aam galtiyaan jinse bachna hai

  • Jab subquery mein NULL ho sakta ho tab 'WHERE id NOT IN (SELECT ...)' likhna: ek bhi NULL hua to NOT IN zero rows deta hai! 'NOT EXISTS' ya 'LEFT JOIN ... WHERE ... IS NULL' use karo.
  • Window function ko seedha WHERE mein filter karna ('WHERE ROW_NUMBER() OVER (...) <= 3'). SQL window functions se pehle WHERE chalata hai; pehle CTE mein rakho.

✅ Jaldi se check karo

Window function (OVER (PARTITION BY ...)) GROUP BY se kaise alag hai?

  1. GROUP BY har group ko ek row mein samet deta hai; window function har row rakhta hai aur calculated column jodta hai
  2. Dono bilkul ek jaise hain
  3. GROUP BY har row rakhta hai; window function rows mita deta hai
Jawaab dekho

A. GROUP BY har group ko ek row mein samet deta hai; window function har row rakhta hai aur calculated column jodta hai: GROUP BY group ki N rows ko 1 summary row bana deta hai; OVER (...) saari N rows rakhta hai aur window ke upar hisaab lagata hai.

🙋 Seekhne wale yeh poochhte hain

Interviews mein ROW_NUMBER aur DENSE_RANK mein kab kaunsa use karun?

Interviewer se poocho ki ties kaise handle karne hain! Agar tie hone par bhi theek 3 rows chahiye to ROW_NUMBER. Agar barabar wale dono products bina rank skip kiye top 3 mein chahiye to DENSE_RANK.

Kya CTEs subqueries se slow hote hain?

Modern databases aur warehouses (PostgreSQL, BigQuery, Snowflake) mein query planner CTEs ko subqueries ki tarah hi optimise karta hai, aur CTEs padhne aur debug karne mein kahin aasaan hote hain.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

Window functions kya hain? ROW_NUMBER, RANK aur DENSE_RANK samjhao.

💬

Window functions related rows pe calculation karte hain bina unhe GROUP BY ki tarah ek row mein samete. Jaise running total ya har employee ki apne department mein salary rank, OVER (PARTITION BY department ORDER BY salary DESC) se. Ties pe: ROW_NUMBER ties mein bhi 1, 2, 3 jaise unique numbers deta hai, isliye deterministic banane ke liye tie breaker column jodo. RANK ties ko same number deta hai aur phir skip karta hai, jaise 1, 1, 3. DENSE_RANK same number deta hai bina gap, jaise 1, 1, 2. LAG aur LEAD se row ko pichhli ya agli row se compare karte ho.

✅

  • Rows ki window pe calculation, har row bani rehti hai
  • PARTITION BY groups banata hai, ORDER BY order tay karta hai
  • Ties pe ROW_NUMBER vs RANK vs DENSE_RANK
  • Uses: har group mein top N, running totals, badlaav ke liye LAG aur LEAD

: 2026 mein zyaadatar data SQL rounds ka core window functions hain.

Har category mein revenue ke hisaab se top 3 products nikaalne wali query likho.

💬

Main har category ke andar products ko rank karke filter karunga. Pehle subquery ya CTE mein har product ka revenue nikaalo aur DENSE_RANK() OVER (PARTITION BY category ORDER BY revenue DESC) AS rnk jodo. Phir WHERE rnk <= 3 wali rows lo. Bolkar batao ties kaise sambhaal rahe ho: DENSE_RANK tied products rakhta hai, to 3 se zyaada rows aa sakti hain; exactly 3 chahiye to product ID jaise tie breaker ke saath ROW_NUMBER use karo.

✅

  • Har product ka revenue nikaalne ke liye CTE
  • Category ke hisaab se partition kiya window rank
  • Outer query mein rank ≤ 3 filter (window function seedhe WHERE mein filter nahi hota)
  • Ties kaise sambhaale batao

: Classic SQL task. Tie handling samjhaana maturity dikhata hai.

SQL mein CTE (WITH clause) kya hai, aur NULL values ke saath NOT IN chupke se zero rows kyun lauta sakta hai?

💬

CTE ya Common Table Expression ek naam wala temporary result hai jo query ke upar WITH se likha jaata hai. Yeh gehre nested subqueries ke bajaye complex SQL ko step-by-step padhne layak blocks mein tod deta hai. NULL trap ke liye: SQL mein NULL ka matlab unknown hai, to NULL se kisi bhi cheez ki comparison UNKNOWN deti hai. Kyunki x NOT IN (1, 2, NULL) ka matlab x != 1 AND x != 2 AND x != NULL hota hai, agar subquery mein ek bhi NULL ho to poori condition UNKNOWN ho jaati hai aur zero rows lautati hai. Main iske bajaye NOT EXISTS ya LEFT JOIN ... WHERE right.id IS NULL use karta hoon.

✅

  • CTE = WITH ke saath naam wala step; nested subqueries se saaf
  • NULL = unknown, isliye != NULL kabhi TRUE nahi hota
  • Kisi bhi NULL ke saath NOT IN 0 rows lautata hai
  • Surakshit tarike: NOT EXISTS ya LEFT JOIN ... IS NULL

: Dekhta hai ki aap padhne layak SQL likhte ho aur asli duniya ke NULL bugs jaante ho.

📌 Yaad rakho

Step by step likhne ke liye WITH (CTEs) use karo, aur bina detail khoye rows rank ya compare karne ke liye OVER (PARTITION BY ... ORDER BY ...).
