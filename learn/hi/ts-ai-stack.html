🟦 AI products ke liye TypeScript: Next.js routes, AI SDK aur server pe keys

EnglishHinglish

🏠 Asli zindagi ki misaal

Restaurant gas cylinder aur cash box kitchen mein rakhta hai, customer ki table pe kabhi nahi. Customer ko sirf menu aur khaana dikhta hai. AI web app mein API key aur model calls server (kitchen) pe rehte hain; browser (table) sirf sawaal bhejta hai aur jawaab dikhata hai.

💡 Aasaan shabdon mein

Bahut se AI product engineers TypeScript mein ship karte hain kyunki product ek web app hota hai. Typical stack: UI aur API route handlers ke liye Next.js (React), model calls ke liye Vercel AI SDK ya provider ka official SDK, schemas ke liye Zod, Postgres database (aksar embeddings ke liye pgvector ke saath), aur slow jobs ke liye queue. Safe aur tez rakhne ke niyam: kabhi bhi secret key ke saath browser se model call mat karo; key ko server ke environment variable mein rakho aur model ko route handler ya server action se call karo. User ko authenticate karo aur har route pe rate limit lagao, kyunki har request mein paisa lagta hai. Lambe jawaab stream karo; slow kaam (documents index karna, batch summaries) user ko intezaar karwaane ki jagah background job mein bhejo. Ek chhota "ai" module rakho jo model calls ko wrap kare, taaki tokens, cost aur latency ek jagah log ho aur baad mein model badalna aasaan rahe. Data aur evals ke liye Python jaanna phir bhi faaydemand hai, par shaandaar AI features banaane ke liye poora product Python mein badalna zaroori nahi.

🎬 Dekho kaise kaam karta hai

Browser sirf aapke server se baat karta hai. Route user check karta hai, requests limit karta hai aur input validate karta hai, phir ek wrapper model call karta hai aur cost log karta hai. Slow kaam queue mein jaata hai.

🪜 Step by step

  1. Next.js app banao, AI SDK aur provider package jodo, aur API key server environment variable mein rakho (browser wale prefix jaise NEXT_PUBLIC_ wala kabhi nahi).
  2. Har AI feature ke liye ek route handler likho jo user authenticate kare, rate limit lagaye, body ko Zod se validate kare aur model call kare.
  3. Har model call ko ek wrapper module ke peeche rakho jo task, user, tokens, cost, latency aur prompt version log kare.
  4. Chats, documents aur embeddings Postgres (pgvector) mein rakho, har row pe user aur tenant IDs ke saath.
  5. Uploads index karna ya raat ki summaries jaisa slow kaam queue aur worker pe bhejo; UI mein progress dikhao.
  6. Preview environments ke saath deploy karo taaki har pull request ko AI feature test karne aur evals chalane ka live link mile.

🔑 Zaroori shabd

Route handler
Server function (jaise app/api/chat/route.ts) jo requests leta hai aur model call karta hai.
Server-only secret
Server ke environment variable mein rakhi API key, jo browser ko kabhi nahi jaati.
Background job
Request ke bahar queue se hone wala kaam, taaki users ko intezaar na karna pade.
Model wrapper
Ek module jisse har model call guzarta hai, logging, cost aur model badalne ke liye.

👀 Example dekho

typescript
// lib/ai.ts: every model call goes through here
export async function callModel(opts: CallOpts) {
  const started = Date.now();
  const res = await generateText({ model: pickModel(opts.task), ...opts });
  await logUsage({
    task: opts.task, userId: opts.userId,
    inputTokens: res.usage.inputTokens, outputTokens: res.usage.outputTokens,
    ms: Date.now() - started,
  });
  return res;
}

// app/api/summarise/route.ts
export async function POST(req: Request) {
  const user = await requireUser(req);          // auth first
  await rateLimit(user.id, { perMinute: 10 });  // every call costs money
  const { text } = Body.parse(await req.json()); // Zod validates input
  return Response.json(await callModel({ task: "summarise", userId: user.id, prompt: text }));
}

Auth, rate limit, input validate, phir ek wrapper se model call karo jo usage log kare.

⚠️ Aam galtiyaan jinse bachna hai

  • API key ko NEXT_PUBLIC_ variable ya client component se expose karna. Koi bhi copy karke aapka bill badha sakta hai.
  • AI routes pe na auth na rate limit, to bots aur loops model ko hazaaron baar call karte hain.
  • 40 second ka indexing job request ke andar karna, jo serverless platforms pe time out ho jaata hai.

✅ Jaldi se check karo

Next.js app mein secret key ke saath LLM API call kahan honi chahiye?

  1. Browser ke React component mein, taaki tez lage
  2. Server route handler ya server action mein, key server environment variable mein
  3. Browser mein, key ko minified file mein chhupa kar
Jawaab dekho

B. Server route handler ya server action mein, key server environment variable mein: Browser ko bheji koi bhi cheez padhi ja sakti hai, minified ho ya nahi. Keys server pe rehti hain, aur server hi auth aur limits lagata hai.

🙋 Seekhne wale yeh poochhte hain

AI product kaam ke liye TypeScript ya Python?

App aur API ke liye apne product ki bhasha use karo; web products ke liye TypeScript aam hai. Notebooks, data checks aur eval scripts ke liye kaafi Python seekho, jahan Python ke sabse zyaada tools hain.

Kya LangChain jaisa framework zaroori hai?

Shuru mein nahi. Provider SDKs aur ek chhota wrapper zyaadatar product features sambhaal lete hain. Framework tab jodo jab woh saaf kaam bachaaye, jaise complex agents ya kai retrievers.

Aap Next.js app mein AI feature jod rahe ho. Use secure aur tez kaise banaoge?

💬

Browser kabhi model se baat nahi karta. API key server ke environment variable mein rehti hai aur model route handler ya server action se call hota hai. Har AI route user ko authenticate karta hai, rate limit aur per-user budget lagata hai, aur input ko Zod se validate karta hai. Saare model calls ek wrapper se guzarte hain jo tokens, cost, latency aur prompt version log karta hai, jisse model badalna bhi aasaan hota hai. Lambe jawaab client ko stream hote hain. Slow kaam, jaise upload kiye documents index karna, background queue mein jaata hai aur UI mein progress dikhti hai, taaki requests time out na hon. Chats aur embeddings jaisa data Postgres mein har row pe user aur tenant IDs ke saath rehta hai.

✅

  • Key aur model calls sirf server pe
  • Har AI route pe auth, rate limit aur input validation
  • Logging, cost aur model badalne ke liye ek wrapper
  • Lambe jawaab stream; slow jobs queue mein
  • Saare stored data pe user aur tenant IDs
