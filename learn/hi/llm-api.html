🔌 LLM API call karna: keys, requests aur costs

EnglishHinglish

🏠 Asli zindagi ki misaal

Zomato pe order karna: aap request bhejte ho (kya chahiye, kahan chahiye), restaurant use process karta hai, aur aapko response milta hai (khaana). Har order ka paisa lagta hai, aur account login batata hai ki aap kaun ho. LLM API bhi aisa hi hai: aapka code messages ke saath request bhejta hai, model jawaab deta hai, billing tokens ke hisaab se hoti hai, aur API key aapka login hai.

💡 Aasaan shabdon mein

Anthropic aur OpenAI jaise providers apne models internet pe API ke through use karne dete hain. Aap messages ki list (system aur user) aur settings jaise model ka naam, max tokens aur temperature bhejte ho, aur generated text wapas milta hai. API keys secret rakho: environment variables mein daalo, code ya GitHub mein kabhi nahi. Errors aur rate limits ke liye retries aur timeouts ka plan rakho. Streaming jawaab word by word bhejta hai, taaki user ko wait na karna pade. Cost track karo: input tokens plus output tokens, guna price per token.

🪜 Step by step

  1. Provider ke console mein API key banao aur use environment variable mein rakho, code mein kabhi nahi.
  2. Model ka naam, system message (instructions) aur user messages ke saath request bhejo; response se text padho.
  3. Input aur output token counts log karo. Cost = tokens × per token price, isse per user cost ka andaaza lagta hai.
  4. Failures sambhalo: timeout set karo, rate limit (429) aur server errors pe exponential backoff ke saath retry karo, aur sab retries fail hon to friendly message dikhao.
  5. Lambe jawaab stream karo taaki users ko turant text dikhe, aur cost control ke liye max token limit lagao.

🔑 Zaroori shabd

API key
Secret password jo API ko aapka account batata hai.
Rate limit
Ek minute mein maximum kitni requests allowed hain.
Streaming
Jawaab ko banate-banate tukdon mein receive karna.

👀 Example dekho

python
import os, anthropic
client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])

msg = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=300,
    system="You are a concise travel assistant for Indian travellers.",
    messages=[{"role": "user", "content": "3-day Jaipur plan on a budget?"}],
)
print(msg.content[0].text)
print(msg.usage)   # input/output tokens → cost

Key environment variable se aati hai, code mein kabhi paste nahi hoti.

⚠️ Aam galtiyaan jinse bachna hai

  • API keys GitHub pe commit karna. Bots minuton mein dhoondh lete hain; aisa ho to turant key badlo.
  • Browser code se API call karna, jisse key khul jaati hai. Apne server se call karo.
  • Koi usage limit nahi. Ek bug ya misuse bahut bada bill bana sakta hai; budgets aur per user limits lagao.

  2. README mein
  3. app.py mein hard-coded

🙋 Seekhne wale yeh poochhte hain

Kis model se shuru karun?

Feature kaam karta hai yeh prove karne ke liye ek strong general model se shuru karo, phir apne eval set pe chhote, saste models test karo aur jahan quality bani rahe wahan switch karo.

Kya mera data training ke liye use hota hai?

Policies provider aur plan ke hisaab se alag hain. Business API plans aam taur pe default mein aapke data pe train nahi karte, par current terms hamesha check karo.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

Tokens aur context window kya hain, aur product mein kyun matter karte hain?

💬

Tokens text ke woh tukde hain jo model padhta aur likhta hai; English mein ek token lagbhag teen chauthai shabd hai. Context window woh maximum tokens hain jo model ek saath sambhaal sakta hai, jisme prompt, documents, chat history aur jawaab sab shaamil hain. Teen wajah se matter karte hain: cost, kyunki APIs per token charge karti hain; latency, kyunki zyaada tokens mein zyaada time; aur quality, kyunki documents fit na hon to chunna padta hai kya daalein, isiliye retrieval use karte hain.

✅

  • Token ≈ shabd ka hissa; pricing aur limits tokens mein
  • Context window mein input aur output dono
  • Cost, speed aur model kya dekh sakta hai, sab pe asar

: Kya aap cost aur limits ke baare mein soch sakte ho, sirf API call nahi?

Python mein files safely kaise padhte ho, external API kaise call karte ho, aur rate limits ya network errors kaise sambhaalte ho?

💬

Files ke liye main hamesha with open(..., encoding='utf-8') block use karta hoon taaki exception aane pe bhi file apne aap band ho, aur bade datasets ko JSON Lines (.jsonl) se ek baar mein ek line stream karta hoon. API calls ke liye main hamesha explicit timeout deta hoon taaki atka hua server mere worker ko freeze na kare, HTTP status code check karta hoon, aur khaali except ke bajaye TimeoutError ya HTTPError jaise specific exceptions pakadta hoon. Jab LLM API 429 (rate limit) ya 503 de, to main exponential backoff aur random jitter ke saath kuch baar retry karta hoon taaki saare workers ek hi second pe retry na maarein.

✅

  • Files ke liye with context manager aur bade data ke liye .jsonl use karo
  • HTTP / LLM API calls pe hamesha explicit timeout lagao
  • Khaali except nahi, specific exceptions pakdo
  • 429 / 5xx errors ko exponential backoff aur jitter ke saath retry karo

: Har AI engineer roz APIs call karta hai aur files padhta hai; interviewers production aadatein dekhte hain.

LLM se reliable JSON output kaise lete ho?

💬

Pehle provider ka structured output ya JSON mode schema ke saath use karo, jo model ko valid JSON tak seemit karta hai. Doosra, schema simple rakho, saaf field descriptions aur allowed values ke saath, aur temperature kam. Teesra, hamesha code se validate karo, jaise Pydantic se: types, required fields aur ranges check karo. Validation fail ho to error message ke saath ek baar retry karo, phir bhi fail ho to crash ke bajaye safe fallback, jaise item ko manual review ke liye mark karna. Aur failures log karo taaki prompt sudhre.

✅

  • Native structured output ya schema wala JSON mode
  • Simple schema, saaf descriptions, kam temperature
  • Code se validate (jaise Pydantic)
  • Error ke saath retry, phir safe fallback

: Production reliability; AI product engineer interviews mein bahut common.

Aapka LLM feature bahut slow aur mehenga hai. Kya karoge?

💬

Pehle naapta hoon tokens aur time kahan ja rahe hain: prompt size, output size, calls ki ginti. Phir main levers: response stream karo taaki user ko turant text dikhe; prompts aur retrieved context chhote karo; repeat sawaalon ke jawaab cache karo aur lambe fixed system prompts ke liye prompt caching; aasaan requests chhote, saste model pe aur sirf mushkil wali bade model pe bhejo; agent steps kam karo; aur background jobs batch karo. Har change ke baad evals dobara chalao, taaki quality na gire.

✅

  • Pehle naapo: tokens, calls, har step ka time
  • Feel hone wali speed ke liye streaming
  • Chhota context, caching, routing se chhote models, kam steps
  • Har change ke baad evals se quality check

: Cost aur latency ke trade offs 2026 ka bada topic hain.

LLM products responses stream kyun karte hain, aur aap kaise implement karoge?

💬

Poora jawaab banne mein kai second lag sakte hain, par pehle shabd second ke chhote hisse mein ready ho jaate hain. Streaming text bante hi dikhata hai, to product tez lagta hai chahe total time same ho. Implement karne ke liye LLM API streaming on karke call karta hoon, server pe chunks aate hi padhta hoon, aur server sent events ya WebSocket se browser ko bhejta hoon jo UI mein jodta jaata hai. Stop button, beech mein network error, aur JSON validation jaise checks stream khatam hone ke baad sambhaalta hoon.

✅

  • Pehle token ka time vs total time
  • Server chunks padhta hai, SSE ya WebSocket se bhejta hai
  • UI text jodti hai; cancel support
  • Khatam hone ke baad validation aur logging

: Hands on product engineering.

Aisi pipeline design karo jo roz 10,000 documents LLM se process kare, jaise invoices se fields nikaalna.

💬

Naye documents object storage mein lo aur har document ka ek job queue pe daalo. Workers jobs uthaate hain, zaroorat ho to OCR se text nikaalte hain, structured output schema ke saath LLM call karte hain, result code se validate karte hain aur document ID, model version aur prompt version ke saath table mein likhte hain. LLM ki rate limits workers ki tay ginti aur exponential backoff wale retries se sambhaalo. Document ID se processing idempotent rakho taaki retries duplicate na karein. Failures aur low confidence results review queue mein bhejo. Har document ka cost budget ke against track karo, aur accuracy check ke liye outputs ka regularly sample lo.

✅

  • Queue based, har document pe idempotent
  • Structured output plus validation
  • Rate limit handling: concurrency control, backoff retries
  • Dead letter ya review queue; cost aur quality monitoring

: 2026 ka favourite: classic data engineering plus LLM ki haqeeqat.

Form ya database bharne wale feature ke liye LLM se bharosemand JSON kaise loge?

💬

Main code mein ek schema banata hoon, Zod ya Pydantic se, aur use teen tarah use karta hoon: provider ke structured output ya tool calling mode se model ko deta hoon, har response ko usse validate karta hoon, aur apne code mein type ki tarah use karta hoon. Fields chhote aur description wale rakhta hoon, categories ke liye enums, aur jo value na ho sake us field ko nullable rakhta hoon taaki model use banaaye nahi. Validation fail ho to error message ke saath ek baar retry, phir human review. Uske baad bhi business rules plain code mein check karta hoon, jaise totals milna aur IDs hona, aur asli examples ke set pe har field ki accuracy naapta hoon.

✅

  • Model, validation aur types ke liye ek schema
  • Structured output ya tool calling mode, "JSON mein jawaab do" nahi
  • Banaayi values rokne ke liye nullable fields aur enums
  • Validate, error ke saath ek retry, phir fallback
  • Code mein business rules aur field level eval set

: Kya aap aise AI features bana sakte ho jin pe doosra code bharosa kar sake.

Kal se aapke AI feature ka response time double ho gaya. Kaise investigate karoge?

💬

Check karo kya badla: deploys, prompt changes, model version change, ya provider ka status issue. Phir traces se dhoondho kaunsa step slow hua: retrieval, LLM call, tool call ya humara code. Agar LLM call hai, to dekho prompts ya outputs lambe hue ya nahi, jaise bada retrieved context ya aisa prompt change jo jawaab lambe karta hai, ya provider ki latency badhi. Agar humara hai, to database queries, cache hit rate aur traffic volume dekho. Wajah theek karo, zaroorat ho to rollback, aur har step pe latency alert jodo taaki agli baar jaldi pakde.

✅

  • Kya badla? deploys, prompts, models, provider
  • Har step ke traces se jagah dhoondho
  • Token count badalna common wajah
  • Theek ya rollback; har step pe alerts

: AI systems ki systematic debugging.
