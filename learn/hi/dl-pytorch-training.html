🔥 PyTorch practice mein: tensors, autograd aur training loop

EnglishHinglish

🏠 Asli zindagi ki misaal

Basketball mein free throw practice ka ek tay paanch-step rhythm hota hai: pichhle shot ko dimaag se hatao, shot maaro, dekho basket se kitna chooqa, samjho haath kis taraf modna hai, aur woh chhota sudhaar karo. PyTorch ka training step bilkul inhi paanch lines pe chalta hai: zero_grad, forward pass, loss, backward, step.

💡 Aasaan shabdon mein

PyTorch research aur production dono mein standard deep learning framework hai. Data Tensors mein rehta hai (NumPy jaise arrays jo .to('cuda') se GPU pe chalte hain). Jab tensor pe requires_grad=True hota hai, to PyTorch ka autograd har operation record karta hai aur loss.backward() call karte hi saare derivatives apne aap nikal deta hai. Training loop ke har batch mein sabse pehle optimizer.zero_grad() call karna zaroori hai (kyunki PyTorch default mein gradients jodta rehta hai), phir model chalao, loss nikalo, loss.backward() aur optimizer.step() call karo. Evaluation ke waqt memory bachane aur dropout band karne ke liye model.eval() aur 'with torch.no_grad():' lagao.

🪜 Step by step

  1. Apne dataset ko torch.utils.data.Dataset aur DataLoader(batch_size=32, shuffle=True) mein rakho taaki batches aasaani se aayein.
  2. Model aur batches ko ek hi device pe rakho: device = 'cuda' if torch.cuda.is_available() else 'cpu'.
  3. Har training step mein: optimizer.zero_grad() → out = model(x) → loss = criterion(out, y) → loss.backward() → clip_grad_norm_ → optimizer.step().
  4. Mixed-precision training ke liye torch.amp.autocast('cuda', dtype=torch.bfloat16) use karo: yeh GPU memory lagbhag aadhi kar deta hai aur speed badhata hai.
  5. Har epoch ke baad model.eval() aur 'with torch.no_grad():' lagakar validation loss nikalo aur best checkpoint save karo.

🔑 Zaroori shabd

Autograd
PyTorch ka engine jo loss.backward() ke waqt apne aap gradients nikalta hai.
zero_grad()
Pichhle batch ke purane gradients saaf karta hai taaki woh naye batch mein jud na jaayein.
DDP / FSDP (ZeRO)
DDP har GPU pe model copy karta hai; FSDP bade models fit karne ke liye weights, gradients aur optimiser states ko GPUs mein baant deta hai.

👀 Example dekho

python
model.train()
for x, y in train_loader:
    optimizer.zero_grad()          # 1. clear old gradients
    preds = model(x)               # 2. forward pass
    loss = loss_fn(preds, y)       # 3. measure error
    loss.backward()                # 4. compute gradients
    optimizer.step()               # 5. update weights

model.eval()
with torch.no_grad():
    val_preds = model(val_x)

5-line ka PyTorch training loop, aur uske baad memory-safe evaluation.

⚠️ Aam galtiyaan jinse bachna hai

  • Validation ya inference mein model.eval() bhoolna: isse Dropout chalta rehta hai aur BatchNorm galat stats use karta hai!
  • Logging ke liye 'loss.item()' ke bajaye seedha 'losses.append(loss)' likhna, jisse poora computation graph GPU memory mein atka rehta hai aur CUDA OOM ho jaata hai!

✅ Jaldi se check karo

Agar aap PyTorch training loop mein 'optimizer.zero_grad()' likhna bhool jaao to kya hoga?

  1. PyTorch chalne se mana kar dega
  2. Har batch ke gradients ek doosre ke upar judte jaayenge aur weight updates galat ho jaayenge
  3. Model apne aap CPU pe chala jaayega
Jawaab dekho

B. Har batch ke gradients ek doosre ke upar judte jaayenge aur weight updates galat ho jaayenge: PyTorch design ke hisaab se .grad mein gradients jodta hai, isliye har step se pehle unhe saaf karna zaroori hai.

🙋 Seekhne wale yeh poochhte hain

DataParallel (DP) aur DistributedDataParallel (DDP) mein kya fark hai?

Hamesha DDP use karo, DP nahi. DP ek hi Python process mein chalta hai aur GIL ki wajah se slow hota hai; DDP har GPU pe alag process chalata hai aur fast all-reduce se gradients sync karta hai.

DDP ke bajaye FSDP ya DeepSpeed ZeRO kab chahiye?

Jab ek GPU pe poore model, gradients aur Adam optimizer states ki copy fit na ho. FSDP (ZeRO Stage 3) in teenon ko GPUs mein baant deta hai aur zaroorat pe jodta hai.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

PyTorch training loop step-by-step batao aur samjhao ki optimizer.zero_grad(), model.eval() aur torch.no_grad() kyun zaroori hain.

💬

PyTorch epoch ke har batch mein paanch steps hote hain: inputs aur targets ko device pe bhejo, optimizer.zero_grad() call karo kyunki PyTorch default roop se gradients jodta rehta hai, forward pass logits = model(x) chalao, loss nikaalo, autograd se gradients nikaalne ke liye loss.backward() call karo, aur weights update karne ke liye optimizer.step() call karo. Validation ya inference ke waqt main model.eval() call karta hoon taaki Dropout band ho aur BatchNorm running statistics use kare, aur forward pass ko with torch.no_grad(): mein rakhta hoon taaki PyTorch computation graph na banaye, jisse memory lagbhag aadhi lagti hai. Bade models ke liye main bf16 mixed precision, gradient clipping aur DDP ya FSDP jodta hoon.

✅

  • 5-step loop: zero_grad → forward → loss → backward → step
  • zero_grad kyun zaroori hai: gradients default roop se batches ke beech judte rehte hain
  • Validation aur inference ke liye model.eval() + torch.no_grad()
  • Production training: bf16 mixed precision, grad clipping, DDP vs FSDP
