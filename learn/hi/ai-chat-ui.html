💬 AI chat UI banana: streaming, stop, retry aur generative UI

EnglishHinglish

🏠 Asli zindagi ki misaal

Chai ki tapri aur aisa restaurant socho jo poori thali tayyar hone par hi sab laata hai. Tapri pe aap chai bante dekhte ho, beech mein "cheeni kam" bol sakte ho, aur pehla ghoont jaldi milta hai. Accha AI chat UI tapri jaisa hai: words likhte likhte dikhte hain, user Stop daba sakta hai, dobara pooch sakta hai ya apna sawaal edit kar sakta hai, aur kuch bhi atka hua nahi lagta.

💡 Aasaan shabdon mein

AI chat screen mein normal form se zyaada state hoti hai. Har message ka role hota hai (user ya assistant), content jo streaming ke dauraan badhta hai, aur status: pending, streaming, done, stopped ya failed. Server model ko stream on karke call karta hai aur chunks ko Server-Sent Events (SSE) ya streamed HTTP response se browser ko bhejta hai; browser har chunk ko aakhri assistant message mein jodta hai. User ko lamba jawaab rokna (AbortController request aur model call dono cancel karta hai, to paisa bhi bachta hai), jawaab dobara banwana, aur pichhla sawaal edit karna aana chahiye. Jawaab ko safe Markdown ki tarah dikhao (HTML sanitise karo taaki model koi script na ghusa sake), scroll ko neeche tabhi chipkao jab user ne upar scroll na kiya ho, aur tool ki activity dikhao jaise "Aapke orders dhoondh raha hoon…". Generative UI ek kadam aage hai: jab model tool call karta hai, UI plain text ki jagah asli component dikhata hai (order card, chart, form). Vercel AI SDK (useChat, streamText) jaisi libraries React aur Next.js apps ke liye zyaadatar kaam sambhaal leti hain.

🎬 Dekho kaise kaam karta hai

Browser sawaal aapke server route ko bhejta hai, server model ke words SSE se wapas stream karta hai, aur har word aate hi dikhta hai. Stop request aur model call dono cancel karta hai.

🪜 Step by step

  1. Har message ko { id, role, parts, status } ki tarah rakho jahan status pending, streaming, done, stopped ya failed ho, taaki UI ko hamesha pata ho kya dikhana hai.
  2. Send karte hi user message aur ek khaali assistant message turant jodo (optimistic UI), send band karo, aur pehle token tak typing indicator dikhao.
  3. Server route se SSE ya streamed response ke zariye stream karo, chunks assistant message mein jodo, aur re-renders ko throttle karo (jaise har 50 ms) taaki lambe jawaab atkein nahi.
  4. Stop ko AbortController se jodo jo fetch aur model call dono cancel kare; adhoora text rakho aur stopped mark karo. Regenerate aur Edit question jodo.
  5. Markdown sanitiser ke saath dikhao, code ko copy button ke saath highlight karo, aur auto scroll sirf tab karo jab user pehle se neeche ho.
  6. Tool steps ko status lines ki tarah dikhao ("Order A12345 dekh raha hoon…") aur tool results ko components ki tarah dikhao jaise order card, raw JSON nahi.
  7. Har message pe Retry button ke saath errors sambhalo, conversation save karo taaki refresh pe kho na jaaye, aur slow 3G aur phone pe test karo.

🔑 Zaroori shabd

SSE (Server-Sent Events)
Server se browser tak ek taraf ka simple stream, tokens stream karne ke liye best.
AbortController
Browser API jo Stop dabane par chalti hui request cancel karti hai.
Generative UI
Model ke tool calls se sirf text nahi, asli components dikhana.
Time to first token (TTFT)
Pehla word dikhne mein kitna time laga; users ko sabse zyaada yahi mehsoos hota hai.

👀 Example dekho

typescript
// app/api/chat/route.ts (Next.js + Vercel AI SDK)
import { streamText } from "ai";
import { anthropic } from "@ai-sdk/anthropic";

export async function POST(req: Request) {
  const { messages } = await req.json();
  const result = streamText({
    model: anthropic(process.env.CHAT_MODEL!), // model id kept in config, easy to upgrade
    system: "You are a helpful support assistant. Answer briefly.",
    messages,
    abortSignal: req.signal,          // Stop button cancels the model call too
  });
  return result.toUIMessageStreamResponse(); // streams chunks to the browser
}

// app/page.tsx
const { messages, sendMessage, stop, regenerate, status } = useChat();
// status: "submitted" | "streaming" | "ready" | "error"
// show <button onClick={stop}> while streaming, <button onClick={regenerate}> after

Server stream karta hai, client jodta hai, aur Stop request aur model call dono cancel karta hai.

⚠️ Aam galtiyaan jinse bachna hai

  • Model output ko raw HTML ki tarah dikhana. Banaaya hua jawaab ya document script ghusa sakta hai; hamesha sanitise karo.
  • Stop sirf text chhupata hai jabki server likhta rehta hai, to aap un tokens ka bhi paisa dete ho jinhe koi nahi padhta.
  • User jab jawaab ka pehle wala hissa padh raha ho tab bhi scroll ko zabardasti neeche le jaana.

✅ Jaldi se check karo

User lambe jawaab ke beech mein Stop dabata hai. Kya hona chahiye?

  1. Poora message delete karke error dikhao
  2. Request aur model call cancel karo, adhoora text rakho, aur message ko stopped mark karo
  3. Screen pe stream chhupa do par model ko background mein likhte rehne do
Jawaab dekho

B. Request aur model call cancel karo, adhoora text rakho, aur message ko stopped mark karo: Model call abort karne se kharch bachta hai aur server free rehta hai, aur adhoora jawaab rakhna user ne jo padha uski izzat karta hai.

🙋 Seekhne wale yeh poochhte hain

Streaming ke liye SSE ya WebSockets?

Model ke jawaabon ke liye SSE (ya streamed HTTP response) kaafi hai kyunki data ek taraf jaata hai aur zyaadatar proxies se chal jaata hai. WebSockets tab use karo jab browser ko bhi server ko stream karna ho, jaise live voice.

Kya Vercel AI SDK zaroori hai?

Nahi, par time bachaata hai: streaming formats, message state, tool calls aur kai providers sambhaal leta hai. Ek baar samjho neeche streaming kaise kaam karti hai, phir jo team use karti hai woh use karo.

Kya AI features hamesha chat hone chahiye?

Nahi. Bahut se behtareen AI features maujooda screen ke andar ek button hote hain ("Summarise", "Draft reply") jo ek panel mein stream karta hai. Chat khule sawaalon ke liye use karo.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

LLM products responses stream kyun karte hain, aur aap kaise implement karoge?

💬

Poora jawaab banne mein kai second lag sakte hain, par pehle shabd second ke chhote hisse mein ready ho jaate hain. Streaming text bante hi dikhata hai, to product tez lagta hai chahe total time same ho. Implement karne ke liye LLM API streaming on karke call karta hoon, server pe chunks aate hi padhta hoon, aur server sent events ya WebSocket se browser ko bhejta hoon jo UI mein jodta jaata hai. Stop button, beech mein network error, aur JSON validation jaise checks stream khatam hone ke baad sambhaalta hoon.

✅

  • Pehle token ka time vs total time
  • Server chunks padhta hai, SSE ya WebSocket se bhejta hai
  • UI text jodti hai; cancel support
  • Khatam hone ke baad validation aur logging
