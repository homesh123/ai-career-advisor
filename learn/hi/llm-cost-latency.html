⚡ Cost aur latency: caching, model routing aur token budgets

EnglishHinglish

🏠 Asli zindagi ki misaal

Busy dabbawala har lunch box dene ke liye senior manager nahi bhejta, aur abhi abhi bana same order dobara fresh nahi pakaata. Simple delivery sabse tez insaan ko jaati hai, repeat order tayyar maal se diye jaate hain, aur sirf khaas requests pe extra mehnat hoti hai. Acche AI products models ke saath yahi karte hain: aasaan kaam ke liye chhota tez model, repeat ke liye cached jawaab, aur bada model sirf zaroorat pe.

💡 Aasaan shabdon mein

Har AI feature ki ek cost per request hoti hai (input tokens plus output tokens, model ki price se guna) aur ek latency (pehle token tak ka time, phir total time). Pehle din se har feature ke liye dono naapo: p50 aur p95 latency, cost per request aur cost per active user. Main levers: (1) Model routing: classification ya chhote rewrites jaise simple kaam chhote, saste model ko bhejo aur sirf mushkil kaam bade model ko; badalne se pehle evals se quality check karo. (2) Prompt caching: providers lamba, na badalne wala shuruaati hissa (system prompt, tool definitions, bada document) cache kar sakte hain, jisse repeat calls sasti aur tez hoti hain; woh hissa bilkul same aur sabse pehle rakho. (3) Response ya semantic caching: agar wahi, ya bahut milta julta, sawaal haal hi mein answer hua ho to saved jawaab do, lekin cache key mein user ya tenant zaroor daalo taaki ek insaan ko kabhi doosre ka jawaab na dikhe, aur data badalne pe entries expire karo. (4) Kam tokens: chhote prompts, reranking ke baad kam chunks, aur output length pe limit. (5) Tez mehsoos karwana: stream karo, retrieval aur doosre calls parallel chalao, aur progress dikhao. (6) Jo abhi zaroori nahi woh batch ya background mein, aksar kam price pe.

🎬 Dekho kaise kaam karta hai

Pehle cache dekho (key mein user ke saath). Miss hone pe router aasaan requests chhote saste model ko aur mushkil requests bade model ko bhejta hai. Har call ki cost aur latency log karo.

🪜 Step by step

  1. Har call ke tokens, cost aur latency (pehle token tak aur total) log karo, feature, model aur prompt version ke tag ke saath.
  2. Har feature ka cost per request, cost per active user aur p50/p95 latency ka dashboard banao, monthly budget alert ke saath.
  3. Sabse zyaada kharch wala hissa dhoondho aur uske liye chhota model try karo; switch tabhi rakho jab evals tay limit ke andar rahein.
  4. Lamba prompt prefix har call mein same rakho aur prompt caching on karo; cache hit rate naapo.
  5. Repeat sawaalon ke liye response cache lagao, key mein identity aur sahi expiry ke saath.
  6. Tokens kam karo: chhote instructions, kam reranked chunks, max output tokens; phir baaki steps stream aur parallel karo.

🔑 Zaroori shabd

Model routing
Kaam kitna mushkil hai uske hisaab se har request ke liye chhota ya bada model chunna.
Prompt caching
Provider lamba, na badla prompt prefix dobara use karta hai taaki repeat calls sasti aur jaldi shuru hon.
Semantic cache
Haal ke sawaal jaisa hi matlab rakhne wale sawaal ke liye saved jawaab dena.
p95 latency
Woh time jismein 95% requests poori hoti hain; yeh woh slow experience dikhata hai jiski users shikaayat karte hain.

👀 Example dekho

python
def answer(user, question):
    key = f"{user.tenant}:{normalise(question)}"        # tenant in the key: no cross-user leaks
    if (hit := cache.get(key)):
        return hit                                       # ~5 ms, ₹0
    model = "small" if classify_difficulty(question) == "easy" else "large"
    res = llm.generate(
        model=model,
        system=[{"text": LONG_POLICY_PROMPT, "cache": True}],  # same prefix every time → prompt cache
        messages=[{"role": "user", "content": question}],
        max_tokens=400,
    )
    metrics.record(model=model, cost=res.cost, ms=res.latency_ms)
    cache.set(key, res.text, ttl=3600)
    return res.text

Pehle cache dekho, mushkil ke hisaab se route karo, lamba prefix cacheable rakho, output pe limit lagao, aur cost aur latency record karo.

⚠️ Aam galtiyaan jinse bachna hai

  • Har step ke liye sabse bada model use karna, simple classification ke liye bhi, "safe rehne ke liye".
  • Bina user ya tenant identity ki cache key, jo ek customer ka jawaab doosre ko leak kar sakti hai.
  • Average latency sudhaarna jabki p95 users 12 second intezaar karte hain. Users slow cases yaad rakhte hain.

✅ Jaldi se check karo

Aap internal HR assistant mein response cache lagate ho. Cache key mein kya zaroor hona chahiye?

  1. User ya tenant ki pehchaan aur permissions, saath mein normalised sawaal
  2. Sirf sawaal ka text, taaki zyaada requests cache se milein
  3. Din ka time, taaki jawaab har ghante refresh hon
Jawaab dekho

A. User ya tenant ki pehchaan aur permissions, saath mein normalised sawaal: Key mein pehchaan na ho to ek insaan ke private data se bana jawaab kisi aur ko mil sakta hai. Yeh data leak hai, speed ki jeet nahi.

🙋 Seekhne wale yeh poochhte hain

Banaane se pehle cost kaise andaaza lagaayein?

Roz ki expected requests ko average input aur output tokens aur model prices se guna karo, phir retries aur growth ke liye 30% jodo. Har kaam ki value se compare karo.

Kya streaming se cost kam hoti hai?

Nahi, yeh mehsoos hone wali latency kam karti hai: users ko shabd jaldi dikhte hain, par tokens utne hi bante hain. Haan, users jaldi rok sakte hain, jisse kuch tokens bachte hain.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

Aapka AI feature har user pe bahut mehnga pad raha hai. Quality bigaade bina cost kaise kam karoge, step by step batao.

💬

Pehle naapta hoon: feature, model aur prompt version ke hisaab se cost per request aur per active user, taaki pata chale paisa kahan ja raha hai. Phir risk ke order mein levers lagata hoon. Classification ya query rewriting jaise simple steps chhote model ko bhejta hoon aur switch tabhi rakhta hoon jab evals tay limit ke andar rahein. Lamba system prompt prefix har call mein same rakhta hoon aur prompt caching on karta hoon. Repeat sawaalon ke liye response cache lagata hoon, cache key mein user ya tenant ke saath taaki kisi ko doosre ka jawaab na dikhe. Chhote instructions, reranking ke baad kam chunks aur max output length se tokens kam karta hoon. Jo turant zaroori nahi woh batch mein. Pehle aur baad ki cost quality scores ke saath report karta hoon.

✅

  • Pehle feature, model aur version ke hisaab se cost naapo
  • Aasaan steps chhote models ko, evals se check
  • Stable prefix ke saath prompt caching
  • Key mein identity ke saath response cache
  • Kam tokens aur jahan ho sake batch; quality ke saath pehle aur baad dikhao

: Cost ki samajh, 2026 ke sabse aam production sawaalon mein se ek.

Har feature ki cost aur p95 naapo; aasaan kaam chhote model ko, identity ke saath safe caching, tokens kam karo, stream aur parallel chalao.
