🧪 Code mein AI features test karna: mocks, recorded responses aur contract tests

EnglishHinglish

🏠 Asli zindagi ki misaal

Driving school student ki asli sadak pe driving check karne se pehle har baar gaadi ke brakes, lights aur indicators ek hi tarah test karta hai. Normal tests brake check hain: tez aur dohraane layak. Evals road test hain: driving ki quality parakhte hain. Acche AI product ko dono chahiye.

💡 Aasaan shabdon mein

Model ke jawaab badalte hain, par model ke aas paas ka zyaadatar code normal code hai jise baaki code ki tarah test karna chahiye: prompts banana, outputs parse aur validate karna, tools chunna, retries aur fallbacks, permission checks aur UI states. Kuch layers use karo. Unit tests model ki jagah ek nakli (fake) rakhte hain jo tay responses deta hai, kharab bhi (galat JSON, khaali jawaab, timeout, 429), taaki check kar sako aapka code har case sambhaalta hai; yeh tez aur free hain. Recorded response tests asli model responses ek baar save karte hain (fixtures) aur unhe replay karte hain, taaki poore flow ka test har baar API call kiye bina chale; prompt ya model badlo to dobara record karo. Contract tests check karte hain ki outputs aapke schema se match karein aur prompt builder kabhi doosre users ka data leak na kare. Kuch live smoke tests schedule pe asli model call karte hain taaki provider ke badlaav pakde jaayein. Evals sabse upar quality parakhte hain. Default test run tez aur offline rakho; kisi flaky live call ko har pull request rokne mat do.

🎬 Dekho kaise kaam karta hai

AI features ke liye testing pyramid: nakli model ke saath bahut se tez unit tests, kuch replay kiye recorded responses, schedule pe thode live smoke tests, aur bagal mein quality parakhte evals.

🪜 Step by step

  1. Har model call ko ek function mein wrap karo taaki tests uski jagah nakli rakh sakein.
  2. Nakli model ke saath unit tests likho, sahi raaste ke liye aur kharab cases ke liye: galat JSON, khaali text, timeout, 429.
  3. Kuch asli responses fixtures ki tarah record karo aur end to end tests mein replay karo; prompt ya model badle to dobara record karo.
  4. Contract tests jodo: outputs schema se match karein, prompts mein sirf current user ka data ho, tools ko validated arguments milein.
  5. Pull requests se alag, schedule pe chhota live smoke test chalao, aur fail ho to alert karo.
  6. Evals ko quality parakhne wala alag job rakho, aur dono ko CI checklist mein jodo.

🔑 Zaroori shabd

Fake / mock model
Nakli model jo tay responses deta hai taaki tests tez, free aur dohraane layak hon.
Fixture (recorded response)
Saved asli model response jo API call ki jagah tests mein replay hota hai.
Contract test
Test jo check karta hai ki outputs aur inputs tay schema ya rule maanein.
Smoke test
Chhota live check, aksar schedule pe, ki asli integration abhi bhi kaam karta hai.

👀 Example dekho

typescript
import { test, expect, vi } from "vitest";
import { classifyTicket } from "../lib/classify";
import * as ai from "../lib/ai";

test("invalid JSON from the model → one retry, then 'other'", async () => {
  const call = vi.spyOn(ai, "callModel")
    .mockResolvedValueOnce({ text: "Sure! The category is billing" })  // not JSON
    .mockResolvedValueOnce({ text: "{oops" });                          // still bad
  const res = await classifyTicket("Refund not received");
  expect(call).toHaveBeenCalledTimes(2);       // retried once
  expect(res.category).toBe("other");          // safe fallback, no crash
});

test("prompt never includes another tenant's documents", async () => {
  const prompt = await buildPrompt({ tenant: "acme", question: "leave policy" });
  expect(prompt).not.toContain("globex");
});

Nakli model se aap kharab raaste (galat JSON, retries, fallbacks) aur data isolation milliseconds mein test kar sakte ho.

⚠️ Aam galtiyaan jinse bachna hai

  • Har unit test mein asli model call karna, jisse CI slow, mehnga aur bina wajah red hota hai.
  • Sirf sahi raasta test karna, to pehla bigda response production crash kar deta hai.
  • Evals aur tests ko ek hi cheez samajhna; dono chahiye.

Jawaab dekho

A. Nakli model aur recorded responses use karo taaki tests tez aur dohraane layak hon; kuch live smoke tests schedule pe chalao: Live calls har test ko slow, mehnga aur flaky banaati hain. Fakes aur fixtures aapke code ka logic bharose se test karte hain, smoke tests asli integration dekhte hain, aur evals quality parakhte hain.

🙋 Seekhne wale yeh poochhte hain

Jiska output har baar badalta hai use kaise test karein?

Un hisson ko test karo jo nahi badalne chahiye: fake responses ke saath code ka logic, schemas se outputs ki shape, aur simple checks se zaroori facts. Wording ko evals se parkho.

Kya tests mein temperature 0 hona chahiye?

Live smoke tests ke liye kam temperature variation kam karta hai par poora khatam nahi karta. Isiliye main test suite fakes aur fixtures use karta hai.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

LLM call karne wale code ke liye automated tests kaise likhte ho?

💬

Main code ki sahi hone aur jawaab ki quality ko alag rakhta hoon. Saare model calls ek function se guzarte hain, to unit tests mein use ek nakli se badal deta hoon jo tay responses deta hai, kharab bhi jaise galat JSON, khaali jawaab, timeout ya 429, aur apna parsing, retries aur fallbacks check karta hoon. End to end flows ke liye recorded asli responses fixtures ki tarah replay karta hoon, aur prompt ya model badalne pe dobara record karta hoon. Contract tests check karte hain ki outputs schema se match karein aur prompts mein sirf current user ka data ho. Chhota live smoke test schedule pe chalta hai taaki provider ke badlaav pakde jaayein. Jawaab ki quality eval suite alag se parakhta hai. Pull request suite tez, free aur deterministic rehta hai.

✅

  • Unit tests ke liye nakli model, failure cases ke saath
  • End to end flows ke liye recorded responses
  • Schemas aur data isolation ke liye contract tests
  • Schedule pe live smoke tests
  • Quality ke liye evals, tests se alag

: Non-deterministic systems ke aas paas engineering discipline.

📌 Yaad rakho

Model ke aas paas ka code fakes aur fixtures se test karo, contracts aur data isolation check karo, schedule pe smoke tests jodo, aur quality evals ko parakhne do.
