⚖️ Post-training: RLHF, DPO, quantisation aur reasoning models

EnglishHinglish

🏠 Asli zindagi ki misaal

Jis medical graduate ne saari kitabein padh li hain, use laakhon facts pata hain, par mareez se tameez se baat karna, unsafe cheezon se mana karna aur mushkil cases mein step-by-step sochna hospital residency mein hi aata hai. Pre-training kitabein padhna hai; post-training (SFT, RLHF/DPO, aur reasoning RL) residency hai. Aur quantisation us bhaari kitab ko 4-bit shorthand pocket diary mein chhaapna hai taaki jeb mein aa jaaye.

💡 Aasaan shabdon mein

Pre-trained LLM sirf agla shabd predict karta hai. Post-training use stages mein ek madadgaar assistant banata hai: pehle instruction examples pe Supervised Fine-Tuning (SFT), phir preference alignment taaki woh galat jawaabon ke bajaye sahi aur safe jawaab chune. RLHF (PPO ke saath) alag reward model train karta hai aur GPU memory mein chaar models rakhkar reinforcement learning chalata hai. DPO (Direct Preference Optimization) ise aasaan banata hai: sirf policy aur frozen reference model ke saath seedha (chosen, rejected) pairs pe train karta hai. Maths aur coding ke liye reasoning models verifiable answers pe RL se train hote hain taaki model jawaab dene se pehle 'test-time compute' kharch karke apne steps check kare. Aakhir mein, quantisation (FP16 → INT8 ya INT4, AWQ/GPTQ se) model weights aur KV cache ko 2–4× chhota kar deta hai.

🪜 Step by step

  1. Saaf (prompt, ideal response) examples pe Supervised Fine-Tuning (SFT) se shuru karo taaki model sahi format aur tone seekhe.
  2. Preference pairs ikattha karo: ek hi prompt ke liye ek behtar jawaab ('chosen') aur ek kamzor ('rejected').
  3. Chhote learning rate aur KL penalty (beta) ke saath DPO (ya verifiable reasoning ke liye GRPO/RL) chalao taaki model base model se bhatak na jaaye.
  4. Domain fine-tuning mein 10–20% general instruction data milao taaki model apni aam samajh na bhoole (catastrophic forgetting).
  5. Deployment ke liye weights ko INT8 ya 4-bit AWQ/GPTQ mein quantise karo aur ship karne se pehle apne eval set pe accuracy aur speed dono test karo.

🔑 Zaroori shabd

DPO vs RLHF (PPO)
Dono model ko insaani pasand ke hisaab se dhalte hain; DPO bina alag reward model ke seedha preferred vs rejected pairs pe train karta hai.
Post-Training Quantisation (PTQ)
GPU memory ghataane ke liye training ke baad model weights ko 16-bit se 8-bit ya 4-bit integers (jaise AWQ, GPTQ) mein compress karna.
Test-time compute (reasoning)
Mushkil maths, logic ya code sawaalon ka jawaab dene se pehle model ko lamba chain-of-thought sochne aur verify karne dena.

👀 Example dekho

text
70B parameter model memory for weights alone:
  FP16 (2 bytes/param)  → ~140 GB VRAM (needs 2× 80GB GPUs)
  INT8 (1 byte/param)   →  ~70 GB VRAM (fits on 1× 80GB GPU)
  INT4 AWQ (0.5 B/param)→  ~35 GB VRAM (fits on 1× 48GB GPU with room for KV cache)

DPO training row:
  prompt:   "Explain recursion simply"
  chosen:   Clear 4-line explanation with a base case example
  rejected: Rambling 500-word jargon wall

4-bit quantisation weight memory ko 4× ghata deta hai, aur DPO seedha chosen vs rejected pairs se seekhta hai.

⚠️ Aam galtiyaan jinse bachna hai

  • Model ko 4-bit mein quantise karke bina domain eval suite chalaye deploy kar dena: maths, code aur exact extraction pe sabse pehle asar pad sakta hai.
  • DPO ko bahut zyaada epochs ya bahut kam beta pe train karna, jisse model baar-baar repeat hone wala ya nakli text dene lagta hai.

✅ Jaldi se check karo

Classic RLHF (PPO) ke mukaable DPO (Direct Preference Optimization) chalana aksar aasaan kyun hota hai?

  1. DPO bina alag reward model train kiye ya unstable PPO chalaye, seedha preference pairs pe cross-entropy jaise loss se seekhta hai
  2. DPO ko kisi training data ki zaroorat nahi hoti
  3. DPO sirf CPU pe chalta hai
Jawaab dekho

A. DPO bina alag reward model train kiye ya unstable PPO chalaye, seedha preference pairs pe cross-entropy jaise loss se seekhta hai: PPO mein chaar models (actor, critic, reward, reference) memory mein sambhalne padte hain; DPO ko sirf policy aur frozen reference model chahiye.

🙋 Seekhne wale yeh poochhte hain

Activation outliers LLM quantisation ko mushkil kyun banate hain, aur AWQ ise kaise theek karta hai?

Lagbhag 0.1% weight channels mein bahut badi activation values aati hain. Unhe 4-bit mein dabane se accuracy kharab ho jaati hai. AWQ chhote calibration set se un zaroori channels ko pehchaankar unki precision bacha leta hai.

Reasoning model aur normal fast LLM mein kab kaunsa use karun?

Multi-step maths, mushkil code, planning ya gehre analysis mein reasoning model use karo jahan accuracy sabse zaroori hai. Chat, summarisation, extraction aur routing mein normal fast model lagao jahan 1 second se kam mein jawaab chahiye.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

LLM post-training ke liye SFT, RLHF (PPO) aur DPO ki tulna karo. KL penalty kyun zaroori hai?

💬

Supervised Fine-Tuning (SFT) base model ko chune hue (prompt, response) demos ki nakal kara ke instructions maan'na sikhata hai. RLHF insaani pasand ke jodon (chosen vs rejected) se aage jaata hai: yeh alag reward model train karta hai aur PPO reinforcement learning se reward badhata hai, saath mein KL-divergence penalty rakhta hai taaki model SFT reference se bahut door na bhatke aur bakwaas ya chaploosi se 'reward-hack' na kare. Direct Preference Optimization (DPO) us reward + KL objective ko mathematically seedhe preference pairs pe simple binary cross-entropy loss mein badal deta hai, jisse alag reward model aur unstable PPO loop ki zaroorat nahi rehti. Math ya code jaise verify hone wale kaamon ke liye GRPO/RLVR unit-test rewards pe reasoning chains train karta hai.

✅

  • SFT demos ki nakal karta hai; RLHF/DPO (prompt, chosen, rejected) pairs se align karte hain
  • KL-divergence penalty model ko bhatakne aur reward-hacking se rokti hai
  • DPO bina alag reward model ke cross-entropy se seedhe preferences optimise karta hai
  • RLVR / GRPO reasoning models ke liye verifiable code ya math rewards use karta hai

: Research, ML aur Agent engineers ke liye 2026 ka core post-training aur alignment sawaal.

Post-training quantisation (INT8/INT4, AWQ, GPTQ) kaise kaam karta hai, aur activation outliers naive INT4 ko kyun tod dete hain?

💬

Quantisation 16-bit floating-point weights (FP16/BF16) ko scale factor ki madad se 8-bit ya 4-bit integers ke chhote grid pe map karta hai, jisse GPU memory 2× se 4× kam lagti hai aur memory-bandwidth se bandha token generation tez ho jaata hai. Naive round-to-nearest INT4 accuracy gira deta hai kyunki ~6B parameters se upar transformer activations mein kuch bade outlier channels (normal se 100× bade) ban jaate hain; 16 integer buckets ko us range pe failane se saare normal weights zero mein dab jaate hain. AWQ aur GPTQ chhote calibration set se ise theek karte hain: AWQ quantise karne se pehle un 1% weight channels ko scale up karke bacha leta hai jo bade activation outliers se multiply hote hain.

✅

  • FP16/BF16 weights ko INT8/INT4 grids pe map karta hai; VRAM 2–4× kam aur token decoding tez
  • Transformer activation outliers quantisation grid ko kheench ke normal values daba dete hain
  • AWQ / GPTQ calibration data se zaroori weight channels ko bachaate hain
  • Lambe contexts aur bade batch sizes ke liye KV cache (FP8/INT8) bhi quantise karo

: LLM efficiency aur quantisation ki gehri samajh check karta hai.

📌 Yaad rakho

SFT format sikhata hai, DPO/RLHF pasand sikhata hai, reasoning RL mushkil sawaal hal karta hai, aur INT4/INT8 quantisation serving sasti banata hai.
