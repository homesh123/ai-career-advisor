🏛️ ML system design: bade scale pe recommendations, search aur fraud

EnglishHinglish

🏠 Asli zindagi ki misaal

Socho ek popular job ke liye 10,000 applications aayi hain. Aap 10,000 logon ka ek-ek ghante interview nahi le sakte. Isliye aap do-stage funnel chalate ho: pehle 5 second ki tez screening 10,000 mein se 100 candidates chunti hai (retrieval), phir gehra interview top 10 ko rank karta hai (ranking). Har bada ML system — YouTube, Amazon, Swiggy, ads, search — bilkul yahi do-stage design use karta hai.

💡 Aasaan shabdon mein

ML system design interviews mein kabhi seedha 'main neural network lagaunga' se shuru mat karo. Saaf 6-step structure follow karo: (1) Requirements clear karo: business goal, scale, latency budget (jaise 100 ms) aur constraints. (2) ML task frame karo aur offline metrics (AUC, Precision@K, NDCG) aur online business metrics (CTR, conversion, fraud loss) dono chuno. (3) Data aur features: user, item aur context features, offline + online feature store se. (4) Architecture: laakhon items ke liye two-stage candidate generation (fast embedding ANN search) + ranking (GBDT ya deep model); fraud/moderation ke liye fast cascade (rules → halka model → bhaari model). (5) Serving: batch vs real-time, caching, fallbacks. (6) Monitoring: drift, shadow rollout, A/B testing aur feedback loops.

🎬 Dekho kaise kaam karta hai

Two-stage funnel: tez candidate retrieval milliseconds mein 1 crore items ko 300 pe le aata hai, taaki bhaari ranking model 100 ms budget ke andar un 300 ko score kar sake.

🪜 Step by step

  1. Step 1 — Clarify (3–5 min): scale (users, items, QPS), latency SLA (jaise p99 < 150 ms), labels kaise milte hain aur business constraints poocho.
  2. Step 2 — Frame & Metrics (5 min): business goal ko ML task (classification, ranking, regression) mein badlo aur offline metric (PR-AUC, NDCG@10) ko online metric (CTR, conversion, fraud loss) ke saath jodo.
  3. Step 3 — Data & Features (8 min): user, item, interaction aur real-time context features batao; aur samjhao ki offline + online feature store training-serving skew kaise rokta hai.
  4. Step 4 — Model & Funnel (10 min): simple baseline se shuru karo, phir multi-stage funnel banao (candidate generation → ranking → re-ranking/business rules).
  5. Step 5 — Serving, Cold Start & Monitoring (10 min): caching, timeout pe fallback, naye users/items ke liye cold start, shadow deployment, A/B testing aur drift alerts cover karo.

🔑 Zaroori shabd

Two-stage retrieve & rank
Stage 1 laakhon mein se milliseconds mein ~200 candidates nikalta hai; Stage 2 un 200 ko bhaari ranking model se score karta hai.
Offline vs online metrics
Offline metrics (AUC, NDCG) test data pe score karte hain; online metrics (CTR, revenue, retention) A/B test mein asli asar naapte hain.
Cold start
Bina purani history wale naye users ya naye products ke liye content features ya popular defaults se acchi predictions dena.

👀 Example dekho

text
E-commerce recommender (10M products, 120 ms budget):
  1. Candidate generation (25 ms): user embedding → ANN search + trending → 300 items
  2. Feature fetch (20 ms):        online feature store (user + item + session features)
  3. Ranking model (45 ms):        GBDT / deep ranker scores 300 items → P(click), P(buy)
  4. Re-ranking & rules (10 ms):   diversity, out-of-stock filter, business rules → top 20

Har stage items ki ginti kam karta jaata hai aur bache hue items pe zyaada dhyaan deta hai.

⚠️ Aam galtiyaan jinse bachna hai

  • Data pipelines, labels, latency budget, cold start aur online evaluation chhodkar 30 minute sirf neural network layers banane mein lagana.
  • User clicks ko bina bias ka sach maan lena: position #1 pe dikhne wale item pe sirf upar hone ki wajah se zyaada click aate hain (position bias).

✅ Jaldi se check karo

1 crore items wale recommender ke ML system design interview mein aap har request pe bhaari ranking model se saare items score kyun nahi kar sakte?

  1. Users ko random items pasand aate hain
  2. Har request pe 1 crore items score karne se ~100 ms ka latency budget toot jaayega aur compute kharch bahut badh jaayega
  3. Ranking models sirf 2 items score kar sakte hain
Jawaab dekho

B. Har request pe 1 crore items score karne se ~100 ms ka latency budget toot jaayega aur compute kharch bahut badh jaayega: Two-stage funnel tez retrieval (ANN/BM25) se 1 crore items ko kuch sau pe le aata hai, taaki bhaari ranker aasaani se 100 ms ke andar kaam poora kar le.

🙋 Seekhne wale yeh poochhte hain

Search aur recommendation ke training data mein position bias kaise sambhalte hain?

Training ke waqt display position ko feature ki tarah daalo aur serving ke waqt use constant (jaise position 1) rakh do, ya Inverse Propensity Scoring (IPS) se examples ko weight do.

Recommendation systems mein Two-Tower model kya hota hai?

Ek network ('user tower') user features ko vector banata hai, aur doosra ('item tower') item features ko usi space mein vector banata hai. Item vectors pehle se index mein save rehte hain, isliye kisi bhi user ke liye top 200 items dhoondhne mein bas kuch milliseconds lagte hain.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

Feed ranking ya search jaise end-to-end ML system design interview ko kaise structure karte ho?

💬

Main chhe steps ka structure use karta hoon. Pehle, business objective, latency budget (maan lo 150 ms) aur scale clarify karo. Doosra, ML task frame karo aur offline metrics (jaise Recall@100 aur NDCG@10) plus online north-star aur guardrail metrics chuno. Teesra, data aur feature store batao: user history, item metadata, aur real-time session signals jo bina leakage ke point-in-time jude hon. Chautha, do-stage funnel use karo: tez candidate generation (two-tower embeddings + BM25 jo millions items ko 500 pe laaye) aur uske baad rich GBDT ya neural ranker jo un 500 ko score kare, plus diversity aur business rules ke liye re-ranker. Paanchwa, cold start aur position bias cover karo. Chhatha, shadow/A-B rollout aur drift monitoring.

✅

  • Pehle business goal, scale aur latency budget clarify karo
  • Offline ranking metrics (Recall@K, NDCG) vs online business aur guardrail metrics
  • Two-stage architecture: tez candidate retrieval → feature-rich ranker → business rules
  • Cold start, position bias, point-in-time features aur monitoring cover karo

: Dekhta hai ki aap sirf loss function ke bajaye poora production ML funnel design kar sakte ho ya nahi.

2 million products wali e commerce site ke liye recommendation system design karo.

💬

Clarify: recommendations kahan dikhengi, goal (clicks, purchases), latency budget aur available data. Do stages. Candidate generation: 2 million products ko jaldi kuch sau tak laao, collaborative filtering ya two tower embeddings plus category mein popular jaise simple sources se. Ranking: zyaada detailed model, jaise gradient boosting ya neural ranker, user, product aur context features se candidates score karta hai, phir business rules stock aur variety sambhaalte hain. Cold start: naye users ko popular aur contextual items; naye products ke liye category aur text embeddings jaise content features. Offline recall aur NDCG se evaluate, phir purchases pe online A/B test. Precomputed embeddings aur fresh features ke liye feature store se serve.

✅

  • Goal aur latency clarify
  • Do stage: candidate generation, phir ranking
  • Users aur items ka cold start
  • Offline metrics, phir A/B test; feature store ke saath serving

: Classic ML system design.

150 ms latency budget wala real time fraud detection system design karo.

💬

Clarify karo miss hue fraud aur galat decline ki keemat kya hai, aur review team kitna sambhaal sakti hai. Features: stream se nikle real time features jaise is card se pichhle 10 minute mein kitni transactions, plus feature store se historical features; latency ke liye kuch features ka thoda purana hona maan lo. Model: gradient boosting, tabular data pe tez aur mazboot, business trade off ke hisaab se threshold, aur beech ki band manual review ko. Serving: kam latency service, features memory ya Redis mein cached, aur model slow ho to fallback rule. Labels chargebacks se der se aate hain, to drift monitor karo aur regularly retrain karo, aur bilkul naye fraud patterns ke liye rules rakho.

✅

  • Har galti ki keemat clarify
  • Streaming plus stored features; staleness trade off
  • Tez model, review band ke saath threshold
  • Fallback ke saath low latency serving; der se labels, drift, retraining

: Latency, features aur business trade offs ek saath.

📌 Yaad rakho

Scale aur latency clear karo → offline + online metrics → features → retrieve phir rank → fallbacks ke saath serve → drift monitor karo.
