📏 Models ko measure karna: accuracy, precision aur recall

EnglishHinglish

🏠 Asli zindagi ki misaal

Airport security do tarah ki galtiyaan kar sakti hai: ek innocent passenger ko rokna (false alarm), ya asli khatre ko miss karna. Jo scanner kabhi beep hi na kare woh '99.99% accurate' hai, kyunki lagbhag koi khatra hota hi nahi, lekin bilkul bekaar hai! Precision poochta hai: jab beep hua, to kitni baar sahi tha? Recall poochta hai: saare asli khatron mein se kitne pakde?

💡 Aasaan shabdon mein

Accuracy, yaani sahi predictions ka hissa, tab misleading hoti hai jab ek class rare ho, jaise fraud ya bimaari. Hamesha ek baseline se compare karo, jaise 'hamesha sabse common class predict karo'. Precision = sahi positives ÷ jitne aapne flag kiye. High precision matlab kam false alarms. Recall = sahi positives ÷ saare asli positives. High recall matlab kam miss. F1 dono ko combine karta hai. Kaunsa zyaada zaroori hai, yeh har galti ki keemat pe depend karta hai: cancer screening mein recall critical hai. Spam filter mein precision zaroori hai taaki asli emails chhup na jaayein. Regression ke liye MAE (average absolute error) jaise errors use karo.

🎬 Dekho kaise kaam karta hai

1,000 payments mein se 10 fraud hain. Model 20 flag karta hai, jinmein 8 asli hain. Precision 'flagged' row mein dekhta hai, recall 'actually fraud' column mein.

🪜 Step by step

  1. Confusion matrix banao: true positives, false positives, false negatives, true negatives.
  2. Precision = TP ÷ (TP + FP) aur recall = TP ÷ (TP + FN) nikalo.
  3. Business se poochho kaunsi galti mehengi hai: miss hua fraud, ya block hua asli customer?
  4. Threshold khiskao (0.5 pathar ki lakeer nahi) taaki zaroori precision aur recall ka balance mile.
  5. Chuna hua metric test set pe baseline ke saath compare karke report karo.

🔑 Zaroori shabd

Precision
Jitna flag kiya, usmein se kitna sach mein positive tha.
Recall
Saare asli positives mein se kitne pakde gaye.
Confusion matrix
Sahi aur galat yes/no predictions ki 2×2 table.

👀 Example dekho

text
1,000 transactions, 10 are fraud.
Model flags 20; 8 of them are real fraud.

Precision = 8 / 20 = 40%   (many false alarms)
Recall    = 8 / 10 = 80%   (caught most fraud)
Accuracy  = (8 + 978) / 1000 = 98.6%
Baseline 'never fraud' accuracy = 99%  ← beats the model on accuracy!

Accuracy kahani chhupa deti hai. Precision aur recall use dikhaate hain.

⚠️ Aam galtiyaan jinse bachna hai

  • Imbalanced data pe high accuracy ka jashn manana. Dekho 'hamesha nahi' baseline kitna score karta hai.
  • Aisa metric chunna jiski business ko parwah nahi. Translate karo: 'hum 10 mein se 8 fraud pakadte hain aur 500 mein se 1 customer galti se block karte hain'.

✅ Jaldi se check karo

Cancer screening model ke liye aam taur pe kaunsi galti zyaada buri hai?

  1. Dono barabar theek hain
  2. Low recall: asli cases miss karna
  3. Low precision: kuch false alarms
Jawaab dekho

B. Low recall: asli cases miss karna: Miss hua cancer case jaan le sakta hai, jabki false alarm ka matlab bas ek aur test. Isliye recall sabse zaroori hai.

🙋 Seekhne wale yeh poochhte hain

ROC AUC aur PR AUC kya hain?

Dono saare thresholds pe performance summarise karte hain. Rare positives ke liye PR AUC zyaada kaam ka hai kyunki ROC AUC tab bhi accha dikh sakta hai jab precision kharab ho.

Regression ke liye kaunse metrics?

MAE (error ka average size), RMSE (bade errors ko zyaada saza) aur MAPE (percent mein error). Woh chuno jo galtiyon ke asar se match kare.

🎯 Is topic pe interviews mein poochhe jaane wale sawaal

Pehle khud bolkar jawaab dene ki koshish karo, phir model answer kholo.

Precision aur recall samjhao. Kab ek ko doosre se zyaada chunoge?

💬

Precision: model ne jitne positive flag kiye, unme se kitne sach mein positive the. Recall: saare asli positives mein se model ne kitne pakde. Cancer screening ya fraud detection mein asli case miss karna bahut mehenga hai, to high recall chahiye, chahe kuch false alarms aayein. Spam filter mein asli email ko spam mein daalna bura hai, to high precision chahiye. Ek number chahiye to F1 dono ko jodta hai, aur decision threshold badal kar dono ke beech balance badal sakte ho.

✅

  • Precision = positive predictions kitne sahi
  • Recall = asli positives kitne cover hue
  • Kaunsi galti mehengi hai uske hisaab se chuno, example ke saath
  • Threshold trade off control karta hai; F1 dono ko balance karta hai

: Kya aap metric ko business ki keemat se jod sakte ho.

Aapka model 99% accurate hai, par business kehta hai bekaar hai. Yeh kaise ho sakta hai?

💬

Shaayad classes imbalanced hain. Agar sirf 1% transactions fraud hain, to jo model hamesha "fraud nahi" bole woh 99% accurate hai aur ek bhi fraud nahi pakadta. Accuracy yeh chhupa deti hai. Main confusion matrix, rare class ka precision aur recall, aur PR AUC dekhunga. Phir business goal check karunga: shaayad unhe 80% fraud pakadna hai aur false alarms itne kam rakhne hain ki review team sambhaal sake, aur main threshold usi hisaab se tune karunga.

✅

  • Class imbalance accuracy ko misleading banata hai
  • Confusion matrix, precision, recall, PR AUC use karo
  • Metric ko business goal aur team capacity se jodo
  • Fixes: threshold tuning, class weights, resampling

: Kya aap headline number se aage soch sakte ho? 2026 ke interviews mein bahut common.

Asli example ke saath conditional probability aur Bayes' rule samjhao. Base rate itna maayne kyun rakhta hai?

💬

Conditional probability P(A | B) ka matlab hai A ki sambhavna jab B pehle hi ho chuka ho. Bayes' rule condition ko palat deta hai: P(fraud | flagged) barabar P(flagged | fraud) guna P(fraud) bhaag P(flagged). Base rate P(fraud) bahut maayne rakhta hai. Maan lo 1,000 mein se sirf 1 transaction fraud hai, aur detector fraud aur normal dono pe 99% sahi hai. 1,000,000 mein se 100,000 transactions mein woh 100 asli fraud mein se ~99 pakadta hai, par 99,900 normal mein se 1% ko galat flag bhi karta hai—lagbhag 999 jhoothe alarms. To jab model kisi transaction ko flag kare, uske asli fraud hone ka chance sirf ~9% hota hai.

✅

  • P(A | B) = B hone pe A ki probability; Bayes P(signal | event) ko P(event | signal) mein palatta hai
  • Rare event example se dikhao ki base rate kam hone pe false positives kaise haavi hote hain
  • Fraud, medical screening ya moderation mein precision vs recall se seedha jodo
  • Normal distributions ke mukaable skewed/long-tailed distributions ka zikr karo

: Classic probability sawaal jo formula ratne walon ko rare events samajhne walon se alag karta hai.

Imbalanced dataset, jaise 1% fraud, kaise sambhaaloge?

💬

Pehle sahi metric chuno: precision, recall, PR AUC, accuracy nahi. Phir options: class weights taaki rare class ki galti zyaada mehngi pade; resampling, yaani majority ko kam ya minority ko zyaada (SMOTE), sirf training data pe; aur decision threshold tune karna taaki business ko jo recall ya precision chahiye woh mile. Validation split mein bhi same ratio rakho, stratified split se. Aksar rare class ke zyaada examples ya behtar features sabse zyaada madad karte hain.

✅

  • Pehle sahi metric
  • Class weights, resampling (sirf train), threshold tuning
  • Stratified splits
  • Rare class ke liye zyaada data ya behtar features

: Accuracy wale sawaal ka follow up; bahut common.

Spam email classifier kaise banaoge?

💬

Pehle poochho: spam kise kehte hain, aur kaunsi galti badtar hai? Aam taur pe asli email ko spam mein daalna badtar hai, to precision zaroori. Data: spam ya not spam label wale emails. Features: text ko numbers mein badlo, TF IDF se, plus links ki ginti ya sender ki history jaise simple signals. Model: logistic regression ya naive Bayes ka baseline, jo text pe accha chalta hai, phir zaroorat ho to fine tuned chhote language model se compare. Test set pe precision aur recall se evaluate karo, aur aisa threshold chuno jisse false positives bahut kam hon. Service ke roop mein deploy karo, users ke "spam nahi" corrections lo, aur regularly retrain karo kyunki spammers tarike badalte hain.

✅

  • Kaunsi galti badtar hai yeh poochho
  • Text features (TF IDF) plus extra signals
  • Pehle simple baseline
  • Precision focused threshold; feedback aur retraining

: Fresher ka classic design sawaal: acchi reasoning ke saath poori, simple pipeline.

150 ms latency budget wala real time fraud detection system design karo.

💬

Clarify karo miss hue fraud aur galat decline ki keemat kya hai, aur review team kitna sambhaal sakti hai. Features: stream se nikle real time features jaise is card se pichhle 10 minute mein kitni transactions, plus feature store se historical features; latency ke liye kuch features ka thoda purana hona maan lo. Model: gradient boosting, tabular data pe tez aur mazboot, business trade off ke hisaab se threshold, aur beech ki band manual review ko. Serving: kam latency service, features memory ya Redis mein cached, aur model slow ho to fallback rule. Labels chargebacks se der se aate hain, to drift monitor karo aur regularly retrain karo, aur bilkul naye fraud patterns ke liye rules rakho.

✅

  • Har galti ki keemat clarify
  • Streaming plus stored features; staleness trade off
  • Tez model, review band ke saath threshold
  • Fallback ke saath low latency serving; der se labels, drift, retraining

: Latency, features aur business trade offs ek saath.

Baseline ko beat karo, aur har galti ki keemat dekhkar precision vs recall chuno.
