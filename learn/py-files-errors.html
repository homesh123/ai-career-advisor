📂 Files, JSON, APIs and error handling

EnglishHinglish

🏠 Real-life example

When you order food on Swiggy, sometimes the restaurant is busy or your internet drops for a second. The app doesn't crash with a blank screen: it catches the problem, waits a moment and retries, or shows a polite message. In Python, try/except and retries do the same job when reading files or calling APIs.

💡 In simple words

Real AI programs read data from files and talk to web APIs. Use 'with open(...) as f:' so files close automatically even if something goes wrong. APIs and config files usually speak JSON, which Python's json module turns into dictionaries and lists. Because files can be missing, JSON can be malformed and APIs can hit rate limits (HTTP 429), wrap risky calls in 'try / except' to handle expected errors gracefully, log what failed, and retry temporary network failures with exponential backoff.

🪜 Step by step

  1. Open files safely with 'with open("data.json", "r", encoding="utf-8") as f:' so Python closes the file automatically.
  2. Parse and write JSON with json.load(f), json.loads(text) and json.dumps(data, indent=2).
  3. Read API keys from environment variables (os.environ["API_KEY"]) loaded from a .env file, never hard-coded.
  4. Wrap external I/O (file reads, HTTP calls, JSON parsing) in try / except for specific errors like json.JSONDecodeError or httpx.TimeoutException.
  5. Retry transient failures (HTTP 429 rate limit or 503 overload) with exponential backoff (1s, 2s, 4s + random jitter) and a max retry cap.

🔑 Key terms

Context manager (with)
Opens a file or connection and closes it automatically when the block ends.
try / except
Runs code that might fail and catches specific errors instead of crashing.
Exponential backoff
Waiting 1s, then 2s, then 4s between retries when an API is overloaded.

👀 See it in action

python
import json, time

with open("orders.json") as f:
    orders = json.load(f)

def call_with_retry(fn, retries=3):
    for attempt in range(retries):
        try:
            return fn()
        except TimeoutError:
            if attempt == retries - 1:
                raise
            time.sleep(2 ** attempt)   # 1s, 2s, 4s

Read JSON safely with 'with', and retry temporary timeouts with exponential backoff.

⚠️ Common mistakes to avoid

  • Writing a bare 'except:' that swallows every error silently, including typos in variable names. Always catch specific exceptions and log them.
  • Retrying permanent errors like HTTP 400 (bad request) or 401 (wrong API key). Only retry temporary errors like 429, 502, 503 or timeouts.

✅ Quick check

Why should you open files using 'with open(...) as f:' instead of just 'f = open(...)'?

  1. Python closes the file automatically, even if an error happens inside the block
  2. It makes the file smaller
  3. It only works for JSON files
Show answer

A. Python closes the file automatically, even if an error happens inside the block: The 'with' block guarantees the file is closed cleanly as soon as the block finishes or raises an error.

🙋 Questions learners ask

Why add random jitter to exponential backoff?

If 100 workers hit a rate limit at the same second and all wait exactly 2 seconds, they will all slam the server together again. Adding a small random delay spreads the retries out.

What is JSON Lines (.jsonl) and why is it used in AI?

A file where each line is one valid JSON object. You can stream it line by line without loading a huge 10 GB file into memory at once, making it ideal for training and eval datasets.

🎯 Asked in interviews on this topic

Try answering out loud first, then open the model answer.

How do you safely read files, call an external API and handle rate limits or network errors in Python?

💬

For files, I always use a with open(..., encoding='utf-8') block so the file closes automatically even if an exception happens, and I stream large datasets with JSON Lines (.jsonl) one line at a time. For API calls, I always pass an explicit timeout so a hung server never freezes my worker, check the HTTP status code, and catch specific exceptions like TimeoutError or HTTPError rather than a bare except. When an LLM API returns 429 (rate limit) or 503, I retry a few times with exponential backoff and random jitter so all workers don't retry at the exact same second.

✅

  • Use with context managers for files and .jsonl for large data
  • Always set an explicit timeout on HTTP / LLM API calls
  • Catch specific exceptions, never bare except
  • Retry 429 / 5xx errors with exponential backoff and jitter

: Every AI engineer calls APIs and reads files daily; interviewers look for production habits.

How do you use Git and pull requests in an AI project, and what should never be committed?

💬

I keep main deployable and do all work on short lived feature branches. Each commit is a small, logical change with a clear message explaining why. Before opening a pull request, I run tests and linters locally, and in the PR description I include what changed, how I tested it, and for AI changes the before and after evaluation scores. I never commit API keys, .env files, customer data, large datasets or model weights to Git; those go into .gitignore, secrets live in environment variables or a secret manager, and large artifacts go to object storage or a model registry.

✅

  • Feature branches, small commits, clear PR descriptions with eval results
  • Never commit .env secrets, raw customer data, or huge model files
  • Use .gitignore, secret managers and artifact storage
  • Review code and prompt changes with the same discipline

: Checks basic software engineering hygiene before letting you near a production repo.

📌 Remember

Use 'with' for files, json for API data, and specific try/except with backoff for network calls.
